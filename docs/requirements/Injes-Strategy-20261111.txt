# Codex 개발 요구사항 — Inje's Strategy

## 0. 프로젝트 및 작업 범위

대상 저장소: https://github.com/BaDook2/C-_STOCK

새로운 매매 전략 체계의 명칭은 **Inje's Strategy**로 한다.

기존 프로젝트의 전략 계산 로직은 교체 대상으로 간주한다. 단, 이미 구현된 데이터 수집, 저장, 차트, 계좌 연결, 백테스트, 주문 관리, 위험 관리, UI 등의 기능은 가능한 한 재사용한다.

**이번 작업의 핵심은 전략 로직 전체를 새롭게 설계하고 구현하는 것이다.**

필수 원칙:

- 기존 Windows WPF 및 macOS Avalonia 화면의 레이아웃은 변경하지 않는다.
- 새로운 탭, 창, 버튼, 설정 화면을 만들지 않는다.
- 기존 전략 설정의 저장·선택·불러오기 기능을 최대한 재사용한다.
- 기존 핵심전략 D 및 이에 종속된 매매 판단 규칙은 새로운 전략에 포함하지 않는다.
- 과거 전략 D의 실행 기록과 설정을 무조건 삭제하지 않는다.
- 기존 프로그램의 다른 필수 기능이 손상되지 않도록 한다.
- 미국주식, 특히 미국 페니스탁의 실시간 틱 단위 매매를 우선 대상으로 한다.
- 실계좌 주문은 기존 안전 잠금 상태를 유지한다. 새로운 전략 구현이 완료됐다는 이유만으로 실거래를 자동 활성화하지 않는다.

기존 코드를 억지로 유지할 필요는 없다. 잘못된 설계나 중복 로직은 교체하되, 정상 작동하는 공통 기능까지 불필요하게 재작성하지 않는다.

## 1. Inje's Strategy의 기본 구조

Inje's Strategy는 특정 매매법 하나가 아니라 여러 독립적인 매매 전략을 관리하는 상위 전략 체계다.

최초 구현할 전략은 4개다.

| ID | 전략명 | 핵심 목적 |
|---|---|---|
| momentum-pullback | 급등주 눌림목 매매 | 급등 후 조정과 재상승을 포착 |
| quote-scalping | 호가 스프레드 틱떼기 | Bid 매수·Ask 매도 차익 추구 |
| crash-rebound | 폭락주 초단기 반등 | 급락 후 저점 안정과 반등 포착 |
| support-zone | 저유동성 지지구간 매매 | 주요 지지구간 접근 후 반등 포착 |

**한 실행 세션에서는 반드시 하나의 전략만 활성화한다.**

예를 들어 `momentum-pullback`이 선택됐다면 다른 세 전략은 매수 신호를 생성하거나 주문을 제출해서는 안 된다.

동일 세션에서 여러 종목을 감시하고 매매하는 것은 허용한다. 단, 모든 종목에는 동일하게 선택된 전략을 적용한다.

선택한 전략이 데이터 부족 또는 조건 미충족으로 매매할 수 없더라도 다른 전략으로 자동 전환하지 않는다.

추후 신규 전략을 추가할 때 기존 엔진을 변경하지 않고 전략 구현과 파라미터 정의만 등록하면 작동하는 확장형 구조를 채택한다.

## 2. 전략 실행 엔진 구조

다음 책임을 분리해서 구현한다.

### 2.1 Market Data Engine

실시간 시세와 과거 데이터를 수집·정규화한다.

사용 데이터:

- 개별 체결 가격·수량·거래소 시각
- 최우선 매수·매도 호가와 수량
- 가능하면 L2 호가
- 전일 종가, 당일 시가·고가·저가
- 누적 거래량·거래대금
- 과거 일봉 및 필요할 경우 분봉
- 시가총액·Float
- 거래 가능 상태, 거래정지, 기업행동, 뉴스·공시 위험
- 데이터 제공자가 지원하는 경우 매수·매도 주도 체결 방향

모든 관측 데이터에는 실제 시장 발생 시각, 수신 시각, 원천 제공자, 시퀀스 또는 정렬 식별자, 데이터 사용 가능 시점을 기록한다.

현재 시점에 아직 알려지지 않은 값을 사용하지 않는다.

### 2.2 Feature Engine

원본 데이터에서 다음 공통 지표를 계산한다.

**가격 변화율**

`ReturnPercent = (CurrentPrice / ReferencePrice - 1) × 100`

**고점 대비 하락률**

`DrawdownPercent = (CurrentPrice / ObservedHigh - 1) × 100`

**저점 대비 반등률**

`ReboundPercent = (CurrentPrice / ObservedLow - 1) × 100`

**초당 체결 건수**

`TradesPerSecond = WindowTradeCount / WindowSeconds`

**초당 거래량**

`VolumePerSecond = Sum(TradeSize) / WindowSeconds`

**상대거래량**

`RVOL = CurrentCumulativeVolume / HistoricalAverageCumulativeVolumeAtSameSessionElapsedTime`

RVOL은 가능하면 과거 동일 시장 세션의 동일 경과시간을 기준으로 계산한다. 장 시작 5분의 누적 거래량을 과거 하루 전체 거래량과 직접 비교하지 않는다.

**호가 스프레드**

`Spread = AskPrice - BidPrice`

`SpreadPercent = Spread / BidPrice × 100`

`SpreadTicks = Spread / TickSize`

**호가 불균형**

`OrderBookImbalance = (BidDepth - AskDepth) / (BidDepth + AskDepth)`

분모가 0이면 계산 불가로 처리한다.

**거래량 변화율**

`VolumeRateRatio = CurrentVolumePerSecond / PreviousVolumePerSecond`

**단기 가격 상승률**

`MomentumPercent = (CurrentPrice / PriceAtWindowStart - 1) × 100`

**가격 변동성**

`RealizedVolatility = sqrt(Sum((ln(P_i / P_(i-1)))²)) × 100`

계산 불가능한 경우 0을 대입해 정상 데이터처럼 취급하지 않는다. `MissingData` 상태로 전달한다.

틱 단위 계산은 전체 체결 내역을 매번 다시 순회하지 않고 시간 기반 큐, Rolling Sum, Monotonic Deque 등을 사용해 증분 갱신한다.

### 2.3 Strategy Engine

공통 지표를 전달받아 선택된 전략의 진입·청산 신호를 계산한다.

전략은 직접 주문하지 않는다.

전략의 반환값에는 다음 정보가 포함되어야 한다.

- StrategyId
- Symbol
- SignalId
- SignalType: Enter / Exit / Hold / CancelEntry
- ReferencePrice
- SignalTime
- SignalReason
- 사용된 관측 데이터 시점
- 충족한 조건과 미충족한 조건
- 전략 판단에 사용된 핵심 지표
- 주문 가능 여부 및 차단 사유

매수 신호와 실제 주문 체결은 별개의 사건으로 관리한다.

### 2.4 Execution Engine

전략 신호를 주문으로 변환하고 실제 주문 상태를 추적한다.

최소 상태:

`Created → Submitted → Accepted → PartiallyFilled → Filled`

취소 경로:

`CancelRequested → Cancelled`

실패 경로:

`Rejected / Expired / Unknown`

동일 종목의 미체결 매수가 존재하는 동안 중복 최초 매수를 금지한다.

주문 취소를 요청했다는 이유만으로 취소가 완료됐다고 처리하지 않는다.

### 2.5 Position & Risk Engine

모든 전략이 동일한 계좌·포지션·위험 관리 로직을 사용한다.

보유 수량과 평균 매수가, 청산 가능 수량, 수익률은 실제 확인된 체결을 기준으로 계산한다.

시세 조회 실패나 스크리닝 조건 미충족이 보유 포지션의 손절·청산 평가를 중단시키면 안 된다.

## 3. 공통 파라미터 — 14개

모든 전략에 공통으로 적용되는 파라미터다.

### 종목 필터 5개

| 파라미터 | 의미 | 초기 예시 |
|---|---|---|
| MinPrice | 최소 주가 | $1 |
| MaxPrice | 최대 주가 | $5 |
| MaxMarketCap | 최대 시가총액 | 선택 적용 |
| MinDailyTradingValue | 최소 일 거래대금 | 전략별 초기값 |
| MaxFloat | 최대 유통주식수 | 선택 적용, 1,000만 주 예시 |

시가총액이나 Float 필터가 비활성화되어 있다면 해당 데이터가 없어도 다른 조건을 평가할 수 있다.

반대로 필터가 활성화되어 있고 값이 확인되지 않았다면 통과시키지 않는다.

### 자금·위험 관리 7개

| 파라미터 | 의미 |
|---|---|
| OrderBudget | 신규 진입 1회 최대 투자금 |
| TakeProfitPercent | 기본 목표 익절률 |
| StopLossPercent | 기본 손절률 |
| MaxHoldingSeconds | 체결 이후 최대 보유시간 |
| ReentryCooldownSeconds | 같은 종목의 재진입 대기시간 |
| MaxDailyLossCash | 하루 최대 허용 손실액 |
| MaxConcurrentPositions | 최대 동시 보유 종목 수 |

손절률은 양수로 저장하고 실제 손절가격은 아래 수식으로 산출한다.

`StopPrice = AverageEntryPrice × (1 - StopLossPercent / 100)`

익절가격:

`TakeProfitPrice = AverageEntryPrice × (1 + TakeProfitPercent / 100)`

최대 보유시간은 주문 생성 시점이 아닌 최초 실제 매수 체결 시점부터 측정한다.

### 주문·체결 2개

| 파라미터 | 의미 |
|---|---|
| MaxSpreadPercent | 진입 시 최대 허용 호가 스프레드 |
| OrderTimeoutMilliseconds | 지정가 주문 체결 대기 제한시간 |

위 14개는 공통 전략 설정의 기본 구성이다.

전략에 따라 익절·손절·보유시간 등의 값은 별도 프로필 기본값으로 지정할 수 있지만, 동일한 의미의 설정을 여러 엔진에서 중복 계산해서는 안 된다.

또한 데이터 신선도, 중복 주문, 비정상 호가, 시장 거래정지, 미확인 주문, 최대 계좌 노출과 같은 필수 안전 조건은 별도의 시스템 보호 규칙으로 유지한다.

# 4. 전략 1 — 급등주 눌림목 매매

StrategyId: `momentum-pullback`

## 4.1 전략의 목적

미국 페니스탁 중 당일 거래량과 가격 상승률이 높은 종목을 탐색한다.

강한 상승 이후 일시적인 가격 조정이 발생하고, 저점이 안정되며 다시 매수세가 유입되는 시점에 진입한다.

단순히 상승률이 높다는 이유만으로 매수하지 않는다.

## 4.2 Advanced 파라미터 — 10개

| 변수 | 의미 | 초기 예시 |
|---|---|---|
| MinDayGainPercent | 당일 최소 상승률 | 10% |
| MomentumWindowSeconds | 최근 상승률 탐색기간 | 120초 |
| MinMomentumPercent | 최근 구간 최소 상승률 | 3% |
| MinRVOL | 최소 상대거래량 | 5배 |
| RVOLLookbackSessions | RVOL 비교 거래일 수 | 20일 |
| ReaccelerationVolumeRatio | 반등 시 최소 거래량 재증가 배수 | 1.5배 |
| MinPullbackPercent | 관측 고점 대비 최소 눌림폭 | 3% |
| LowStabilitySeconds | 새로운 저점 없이 유지해야 하는 시간 | 60초 |
| MinReboundPercent | 저점 대비 최소 반등률 | 0.3% |
| MaxChasePercent | 신호가격 대비 최대 추격 허용률 | 0.5% |

모든 값은 수정할 수 있어야 한다.

## 4.3 진입 조건

**1단계: 급등 후보 등록**

다음 조건을 모두 만족해야 한다.

`DayGainPercent >= MinDayGainPercent`

`MomentumPercent >= MinMomentumPercent`

`RVOL >= MinRVOL`

현재가는 정상 체결 데이터로 관측된 가격이어야 한다.

급등 후보가 등록되면 등록 시점부터 고점을 추적한다.

`TrackedHigh = max(TrackedHigh, CurrentPrice)`

**2단계: 눌림 발생**

관측 고점 대비 하락률을 계산한다.

`PullbackPercent = (TrackedHigh - CurrentPrice) / TrackedHigh × 100`

조건:

`PullbackPercent >= MinPullbackPercent`

이 조건을 충족한 뒤 최저가를 추적한다.

`TrackedLow = min(TrackedLow, CurrentPrice)`

**3단계: 저점 안정**

마지막으로 새로운 저점이 형성된 시점을 기록한다.

`StableSeconds = CurrentTime - LastNewLowTime`

조건:

`StableSeconds >= LowStabilitySeconds`

저점이 다시 갱신되면 안정 시간은 0부터 재시작한다.

이 시간 조건은 거래가 없는 상태에서 단순히 시간이 지났다고 정상으로 인정하면 안 된다. 최근 거래와 호가 데이터가 유효해야 한다.

**4단계: 반등 확인**

`ReboundPercent = (CurrentPrice / TrackedLow - 1) × 100`

조건:

`ReboundPercent >= MinReboundPercent`

반등률이 기준 미만이었다가 기준 이상으로 새롭게 돌파한 사건을 우선 사용한다.

**5단계: 거래량 재유입**

현재 10초 거래량 속도와 그 직전 30초 거래량 속도를 비교한다.

`Reacceleration = Current10SecVolumeRate / Previous30SecVolumeRate`

조건:

`Reacceleration >= ReaccelerationVolumeRatio`

비교 구간에 필요한 체결 데이터가 부족하면 진입하지 않는다.

**6단계: 최종 진입**

모든 조건을 충족하면 매수 신호를 생성한다.

실제 주문가격은 다음 제한을 만족해야 한다.

`OrderPrice <= SignalPrice × (1 + MaxChasePercent / 100)`

급등 이후 과도하게 하락하는 종목을 잘못된 눌림목으로 판단하지 않도록, 원래 상승 조건의 유효성이 사라진 경우 후보를 무효화한다.

고점·저점·반등 판단은 반드시 순서대로 관측된 가격을 사용한다.

## 4.4 청산 조건

초기 실험값:

- 익절 +3%
- 손절 -1.5%
- 최대 보유 60초

세 조건 중 먼저 발생하는 청산 조건을 적용한다.

추가로 유동성 급감이나 매수세 소멸이 감지되면 조기 청산 신호를 만들 수 있도록 내부 확장 지점을 둔다.

단, 명시적으로 설정되지 않은 새 청산 임계값을 임의로 활성화하지 않는다.

# 5. 전략 2 — 호가 스프레드 틱떼기

StrategyId: `quote-scalping`

## 5.1 전략의 목적

체결이 활발하고 호가가 빠르게 변하는 미국 페니스탁을 탐색한다.

매수호가 부근에 지정가 매수 주문을 제출하고 체결되면 매도호가 부근에 지정가 매도 주문을 제출해 짧은 가격 차이를 노린다.

이 전략의 핵심은 가격 상승을 예측하는 것이 아니라 **호가 차이와 체결 가능성을 활용하는 것**이다.

## 5.2 Advanced 파라미터 — 12개

| 변수 | 의미 |
|---|---|
| MinTradesPerSecond | 최소 초당 체결 건수 |
| MinSharesPerSecond | 최소 초당 체결 주식수 |
| VolumeLookbackSeconds | 과거 체결량 비교기간 |
| MinQuoteChangesPerSecond | 최소 초당 호가가격 변경 횟수 |
| MinOrderBookImbalance | 최소 호가잔량 불균형 |
| MinBidSize | 최소 매수호가 잔량 |
| MinAskSize | 최소 매도호가 잔량 |
| OrderBookDepthLevels | 분석할 호가 단계 수 |
| MinSpreadTicks | 최소 목표 스프레드 틱 수 |
| BuyOffsetTicks | 매수 지정가 오프셋 |
| SellOffsetTicks | 매도 지정가 오프셋 |
| VolumeDecayRatio | 거래량 감소 청산 기준 |

정확한 기본값은 거래 종목의 가격 수준과 데이터 해상도에 맞춰 검증 가능한 실험값으로 설정한다.

## 5.3 진입 조건

**1단계: 체결 활성도**

`TradesPerSecond >= MinTradesPerSecond`

`SharesPerSecond >= MinSharesPerSecond`

**2단계: 호가 활성도**

`QuoteChangeFrequency >= MinQuoteChangesPerSecond`

호가 변경 빈도는 최우선 매수 또는 매도 가격이 실제로 변경된 횟수를 기준으로 한다. 단순한 호가 수량 변경과 구분한다.

**3단계: 호가잔량 조건**

`Imbalance = (BidDepth - AskDepth) / (BidDepth + AskDepth)`

조건:

`Imbalance >= MinOrderBookImbalance`

`BidDepth >= MinBidSize`

`AskDepth >= MinAskSize`

L2 데이터가 필요한 설정이면 L1 데이터만으로 L2 조건을 통과시키지 않는다.

**4단계: 스프레드 조건**

`SpreadTicks = (AskPrice - BidPrice) / TickSize`

조건:

`SpreadTicks >= MinSpreadTicks`

추가로 왕복 거래비용을 고려한 기대 차익이 양수여야 한다.

`ExpectedGross = PlannedSellPrice - PlannedBuyPrice`

`ExpectedNet = ExpectedGross - EstimatedRoundTripFees - EstimatedTax - ConservativeExecutionCost`

`ExpectedNet > 0`

이 조건을 만족하지 않으면 주문하지 않는다.

**5단계: 지정가 매수**

`BuyLimitPrice = BestBid + BuyOffsetTicks × TickSize`

가격은 해당 종목·거래소·세션의 유효 호가 단위로 정규화한다.

오프셋 값 때문에 즉시 체결 가능한 시장성 주문으로 바뀌는 경우에도 수동적 지정가 주문과 동일한 체결 가정을 적용하지 않는다.

## 5.4 매도 조건

매수 체결이 확인되면 실제 매수가와 최신 호가를 사용하여 매도 목표가를 설정한다.

`SellLimitPrice = BestAsk - SellOffsetTicks × TickSize`

단, 기대 순수익이 양수가 되는 목표가인지 확인해야 한다.

체결되지 않은 매도 주문은 계속 체결된 것으로 가정하지 않는다.

시세가 이동하면 기존 주문의 상태와 취소 확인 여부를 검사한 뒤 주문 변경 또는 재제출을 판단한다.

## 5.5 유동성 약화 청산

매수 직후의 거래량 속도 또는 진입 당시 기준 거래량 속도를 저장한다.

`LiquidityRatio = CurrentVolumeRate / EntryReferenceVolumeRate`

조건:

`LiquidityRatio <= VolumeDecayRatio`

이면 청산을 검토한다.

단, 유동성이 감소한 상황에서 새로운 지정가 주문만 반복 제출하면 청산이 지연될 수 있다.

따라서 유동성 약화, 손절, 최대 보유시간 초과 상황에서는 보호 청산 정책을 우선 적용한다.

## 5.6 가장 중요한 체결 규칙

이 전략은 다른 전략보다 체결 모델의 정확성이 중요하다.

다음 가정을 금지한다.

- Bid 가격에 매수 주문을 넣었다는 이유만으로 즉시 체결 처리
- Ask 가격에 매도 주문을 넣었다는 이유만으로 즉시 체결 처리
- 호가가 주문가격에 도달했다는 이유만으로 전량 체결 처리
- 주문 발생에 사용된 동일 체결 이벤트로 즉시 주문 체결 처리
- 지정가 매수와 지정가 매도 모두 최적의 가격으로 체결됐다고 가정

호가 대기열 정보가 제공되지 않는 경우에는 실제 체결 확률을 정확히 알 수 없으므로 보수적인 대체 체결 모델을 사용한다.

대기열 추정이 불가능하면 `QueuePositionUnknown` 상태를 기록한다.

체결 모델의 낙관적·보수적 시나리오를 구분해서 분석할 수 있도록 설계하되, 낙관적 시나리오의 수익을 실제 재현 가능한 수익으로 표시하지 않는다.

# 6. 전략 3 — 폭락주 초단기 반등

StrategyId: `crash-rebound`

## 6.1 전략 목적

미국주식 중 당일 큰 폭으로 하락한 종목에서 추가 하락이 잠시 멈추고 반등이 발생할 때 초단기로 진입한다.

단순히 하락률이 크다는 이유만으로 매수하지 않는다.

ATM 발행, 상장폐지, 거래정지, 심각한 재무·공시 위험 등으로 하락한 종목에 대해서는 신규 진입을 제한할 수 있어야 한다.

## 6.2 Advanced 파라미터 — 11개

| 변수 | 의미 | 초기 예시 |
|---|---|---|
| CrashReferenceMode | 급락 비교 기준가격 | 전일 종가 |
| MinCrashPercent | 최소 급락률 | 50% |
| CrashLookbackSeconds | 급락 속도 탐색기간 | 300초 |
| MinCrashVelocity | 최소 초당 하락률 | 0, 비활성 |
| CrashVolumeRatio | 급락 중 거래량 증가 배수 | 2배 |
| LowStabilitySeconds | 저점 안정 유지시간 | 60초 |
| LowStabilityTolerancePercent | 저점 안정 허용 변동폭 | 0.2% |
| MinReboundPercent | 저점 대비 최소 반등률 | 0.5% |
| MaxChasePercent | 신호가격 대비 최대 추격 허용률 | 1% |
| LowInvalidationPercent | 저점 재이탈 무효화 폭 | 0.5% |
| RequireFundamentalRiskClearance | 뉴스·공시 위험 확인 필수 여부 | true |

## 6.3 급락 감지

기준가격은 선택한 모드에 따라 달라진다.

- PreviousClose: 전일 종가
- SessionOpen: 당일 시가
- ObservedSessionHigh: 현재까지 관측한 당일 고가

`CrashPercent = (1 - CurrentPrice / ReferencePrice) × 100`

조건:

`CrashPercent >= MinCrashPercent`

급락 속도 필터가 활성화된 경우:

`CrashVelocity = (PriceAtWindowStart - CurrentPrice) / PriceAtWindowStart × 100 / CrashLookbackSeconds`

`CrashVelocity >= MinCrashVelocity`

필요한 구간 데이터가 존재하지 않으면 해당 필터를 통과시키지 않는다.

거래량 증가율 역시 현재 구간과 이전의 동일 길이 구간을 비교해 계산한다.

## 6.4 저점 안정 판단

급락 조건이 충족된 이후의 가격만으로 저점을 추적한다.

`CrashLow = min(CrashLow, CurrentPrice)`

새로운 저점이 발생하면 안정 시간을 초기화한다.

`StableTime = CurrentTime - LastLowUpdateTime`

조건:

`StableTime >= LowStabilitySeconds`

추가로 안정 구간의 가격 변동폭을 검사한다.

`StabilityRangePercent = (StableHigh - StableLow) / StableLow × 100`

`StabilityRangePercent <= LowStabilityTolerancePercent`

이 안정 구간은 마지막 저점 갱신 이후의 실제 관측치로 계산하며, 데이터 공백만으로 안정 상태를 선언하지 않는다.

## 6.5 반등 확인

`BouncePercent = (CurrentPrice / CrashLow - 1) × 100`

조건:

`BouncePercent >= MinReboundPercent`

반등 기준을 새로운 관측 이벤트에서 상향 돌파해야 한다.

후보가 이미 반등한 이후에 만들어졌다는 이유만으로 과거 반등 신호를 소급 생성하지 않는다.

## 6.6 저점 무효화

진입 후보의 기존 저점을 기준으로:

`InvalidationPrice = CrashLow × (1 - LowInvalidationPercent / 100)`

현재가가 이 가격 아래로 내려가면 기존 후보를 무효화한다.

이미 보유 중인 경우에는 이 조건을 전략 청산 사유로 활용할 수 있다.

## 6.7 뉴스·공시 위험

위험 정보는 최소한 다음 상태를 지원한다.

- Cleared: 해당 시점의 검사 범위에서 위험 없음이 확인됨
- RiskDetected: 위험 발견
- Unknown: 확인 불가

`RequireFundamentalRiskClearance = true`이면 Cleared만 신규 진입을 허용한다.

뉴스 제공자가 없다는 이유로 Cleared를 반환하면 안 된다.

검사 대상에는 이용 가능한 범위에서 ATM 및 희석성 발행, 대규모 신주 발행, 거래정지, 상장폐지 위험 등 중요 이벤트를 포함한다.

확인된 위험 정보와 단순 뉴스 부재는 구분한다.

## 6.8 청산

초기 실험값:

- 익절 +5%
- 손절 -2.5%
- 최대 보유시간 60초

거래정지나 유동성 공백으로 손절 주문이 체결되지 않을 수 있으므로, 손절가격과 실제 청산 체결가격을 별도로 기록한다.

# 7. 전략 4 — 저유동성 지지구간 매매

StrategyId: `support-zone`

## 7.1 전략 목적

거래량이 비교적 적은 종목에서 이동평균선, 과거 주요 고점, 가격별 매물대 등이 겹치는 지지구간을 계산한다.

현재 가격이 해당 구간에 접근하면 진입을 고려하고, 짧은 반등에서 수익을 실현한다.

기존의 장기 과매도 전략이나 핵심전략 D를 그대로 가져오는 것이 아니라, 지지구간 계산에 필요한 수학적 개념만 재사용할 수 있다.

저유동성이라는 이유로 무조건 진입을 허용하는 것은 아니다. 매도할 수 없을 정도로 거래가 없는 종목은 공통 위험 관리에서 제외한다.

## 7.2 Advanced 파라미터 — 13개

| 변수 | 의미 | 초기 예시 |
|---|---|---|
| SupportSources | 사용할 지지선 종류 | MA, Pivot, VolumeZone |
| MovingAveragePeriods | 이동평균 기간 목록 | 120,240,480,999 |
| PivotLeftBars | 과거 고점 왼쪽 비교봉 수 | 20 |
| PivotRightBars | 과거 고점 오른쪽 확정봉 수 | 20 |
| VolumeProfileLookbackBars | 근사 매물대 계산기간 | 240봉 |
| VolumeBinSize | 가격 구간 최소 폭 | $0.01 예시 |
| SupportClusterRangePercent | 지지선 병합 허용 거리 | 5% |
| MinimumSupportCount | 최소 중첩 지지선 개수 | 2 |
| SupportDistancePercent | 지지구간 접근 허용 거리 | 3% |
| RequireReboundConfirmation | 반등 확인 사용 여부 | false |
| ReboundPercent | 반등 확인 기준 | 3% |
| MaxAverageDailyTradingValue | 저유동성 종목 선별 상한 | 전략별 지정 |
| SupportBreakPercent | 지지구간 하단 이탈 손절폭 | 3% |

미국주식에 사용할 때 가격 Bin은 달러 단위와 해당 종목의 최소 호가 단위를 고려한다. 기존 국내주식의 100원 기준을 그대로 사용하지 않는다.

## 7.3 이동평균선

완료된 봉의 종가로 산술평균을 계산한다.

`MA(N) = Sum(PreviousNCompletedCloses) / N`

지표별 실제 봉 단위를 명확히 관리한다.

분봉 차트를 표시하고 있더라도 일봉 MA240을 임의로 분봉 MA240으로 대체하지 않는다.

필요한 과거 데이터가 부족한 이동평균선은 생성하지 않는다.

## 7.4 Previous Major High

과거 주요 고점은 Pivot High를 이용해 계산한다.

시점 `i`가 Pivot High가 되려면:

`High[i] > max(High[i-L ... i-1])`

그리고:

`High[i] > max(High[i+1 ... i+R])`

여기서:

`L = PivotLeftBars`

`R = PivotRightBars`

오른쪽 R개 봉이 모두 완성되기 전에는 해당 Pivot을 사용할 수 없다.

현재 시점에 이미 확정된 Pivot만 지지 후보에 등록한다.

## 7.5 Approximate Volume Profile

일봉 OHLCV를 사용하여 근사 매물대를 생성한다.

계산 순서:

1. 각 일봉의 Low~High 가격 구간을 구한다.
2. 해당 구간을 일정한 크기의 Price Bin으로 분할한다.
3. 일봉의 거래량을 해당 가격 구간에 비례해 배분한다.
4. 동일한 Bin에 배분된 거래량을 누적한다.
5. 거래량이 집중된 Bin들을 매물대 후보로 만든다.

예를 들어:

- Low = $2.00
- High = $2.10
- Volume = 100,000주
- BinSize = $0.01

이면 해당 가격 범위가 차지하는 Bin들에 거래량을 분배한다. 구간 경계의 중복 계산으로 전체 배분 거래량이 원래 거래량을 초과하면 안 된다.

이 결과는 실제 개별 체결가격 기반 Volume Profile이 아니라 `ApproximateVolumeZone`으로 명명한다.

추후 실제 틱 기반 Volume Profile을 연결할 수 있도록 데이터 공급과 계산 로직을 분리한다.

## 7.6 Support Cluster

생성된 지지 후보들을 대표가격 기준으로 정렬한다.

인접한 후보의 가격 차이를 계산한다.

`DistancePercent = (RightPrice - LeftPrice) / LeftPrice × 100`

조건:

`DistancePercent <= SupportClusterRangePercent`

이면 동일한 Cluster로 묶는다.

Cluster는 다음을 포함한다.

- ClusterLower
- ClusterCenter
- ClusterUpper
- SupportCount
- SupportTypes
- SupportIds
- KnownAt

인접 가격 연결 방식 때문에 최종 Cluster가 지나치게 넓어지는 경우가 있으므로, 전체 구간의 폭도 검사해 비정상적으로 넓은 Cluster를 거절한다.

하나의 매물대 내부 Bin들을 독립적인 여러 지지 근거로 중복 계산하지 않는다.

## 7.7 지지구간 접근

현재가가 다음 범위에 존재해야 한다.

`ClusterLower × (1 - SupportDistancePercent / 100) <= CurrentPrice`

그리고:

`CurrentPrice <= ClusterUpper × (1 + SupportDistancePercent / 100)`

추가 조건:

`SupportCount >= MinimumSupportCount`

## 7.8 매수 조건

기본 모드:

`RequireReboundConfirmation = false`

이면 지지구간 접근 조건이 충족되고 공통 위험 검사를 통과했을 때 최초 매수 신호를 생성할 수 있다.

반등 확인을 켠 경우에는 최초 지지 접근 이후부터 저점을 추적한다.

`ObservedLow = min(ObservedLow, CurrentPrice)`

`BouncePercent = (CurrentPrice / ObservedLow - 1) × 100`

조건:

`BouncePercent >= ReboundPercent`

반등 확인은 지지구간 접근 이후의 가격만 사용한다.

## 7.9 지지구간 이탈 청산

최초 매수의 근거가 된 ClusterLower를 저장한다.

`SupportStopPrice = ClusterLower × (1 - SupportBreakPercent / 100)`

현재가가 이 가격 이하로 내려가면 지지구간 붕괴에 의한 청산 신호를 생성한다.

실시간 틱매매에서는 일봉 종가까지 기다리는 기존 과매도 전략의 규칙을 자동 적용하지 않는다.

공통 고정 손절과 지지구간 손절 중 먼저 충족된 보호 조건을 적용한다.

# 8. Standard / Advanced 파라미터 변환

기존 Standard와 Advanced의 개념은 유지한다.

두 모드는 별도의 전략이 아니다.

Standard는 간단한 대표 파라미터를 사용하고, Advanced는 실제 계산에 사용되는 상세 수치를 직접 지정한다.

Standard 입력값은 저장 시 또는 실행 설정 생성 시 Advanced 파라미터로 결정론적으로 변환한다.

예를 들어 급등주 눌림목의 거래량 강도가 1~5라면 다음과 같은 초기 매핑 테이블을 사용할 수 있다.

| 거래량 강도 | MinRVOL |
|---|---:|
| 1 | 2배 |
| 2 | 3배 |
| 3 | 5배 |
| 4 | 7배 |
| 5 | 10배 |

다른 강도 항목도 각각 실제 수치로 변환한다.

강도 숫자만 저장하고 내부에서 정체불명의 가중치로 판단하지 않는다.

파라미터 정의에는 최소한 다음 메타데이터를 둔다.

- Key
- Label
- Description
- Unit
- ValueType
- DefaultValue
- MinValue
- MaxValue
- StrictnessDirection
- StandardMapping
- ValidationRule

변환한 Advanced 값은 실제 실행에 사용되는 값과 정확히 같아야 한다.

Advanced에서 직접 수정한 설정을 저장했다가 불러왔을 때 Standard 기본값으로 덮어쓰면 안 된다.

전략별로 Standard 5~6개, Advanced 10~13개를 기본 설계로 유지한다.

# 9. 공통 진입·청산 엔진

## 9.1 주문 수량

공통 계산식:

`AvailableOrderCash = min(OrderBudget, AvailableCash, RemainingExposureLimit)`

`OneShareCost = OrderPrice × (1 + BuyFeeRate)`

`Quantity = floor(AvailableOrderCash / OneShareCost)`

여기서 수수료율은 계산 시 0~1 범위의 비율로 변환한 값을 사용한다.

또한 손절 기준에 따른 위험예산 제한이 적용된다면 다음 상한을 함께 사용한다.

`RiskPerShare = max(0, EntryPrice - ProtectiveStopPrice) + EstimatedRoundTripCostsPerShare`

`RiskQuantity = floor(RemainingRiskBudget / RiskPerShare)`

최종 수량:

`FinalQuantity = min(CashQuantity, RiskQuantity, PositionLimitQuantity)`

손절가격을 산출하지 못하거나 위험예산 계산이 불가능하면 위험제한을 무시한 대량 주문을 생성하지 않는다.

수량이 0주면 주문하지 않는다.

## 9.2 청산 우선순위

최소한 다음 순서로 판단한다.

1. 계좌 긴급중지·거래정지·주문 상태 불일치 등 시스템 안전 상태 확인
2. 보호 손절 및 전략 무효화 조건
3. 최대 보유시간 만료
4. 전략 고유 조기 청산 조건
5. 목표 익절
6. 새로운 매수 신호

다만 기존 보유분에 대한 청산은 신규 진입 스크리너의 통과 여부와 무관하게 계속 평가해야 한다.

긴급중지는 새로운 주문을 차단하고 미체결 주문의 취소를 요청한다. 이미 체결된 보유 포지션은 별도 청산 정책과 계좌 동기화 상태에 따라 관리한다.

## 9.3 틱 단위 평가

전략 진입 판단은 실시간 체결 이벤트 또는 필요한 호가 이벤트가 도착할 때 평가한다.

완성된 분봉이 생길 때만 매수 판단을 수행하도록 제한하지 않는다.

예를 들어 10:00:00.250에 반등 조건이 충족되면 그 이벤트가 유효한 즉시 신호를 생성할 수 있어야 한다.

분봉과 일봉은 보조 지표 계산에 활용할 수 있지만, 실시간 전략 실행 자체를 봉 종료에 종속시키지 않는다.

## 9.4 주문 체결 이후 상태

각 종목의 상태를 최소한 다음과 같이 관리한다.

`Idle → Candidate → EntrySignal → BuyPending → Holding → SellPending → Cooldown`

필요하면 `Blocked`, `UnknownOrder`, `ReconciliationRequired` 상태를 추가한다.

모든 상태 전이는 실제 관측 이벤트와 주문 확인 기록에 의해 결정되어야 한다.

특히 매수 신호가 발생했다는 이유로 곧바로 Holding으로 전환하지 않는다.

## 9.5 재진입

포지션이 전량 청산된 후:

`ElapsedSeconds = CurrentTime - LastConfirmedExitTime`

조건:

`ElapsedSeconds >= ReentryCooldownSeconds`

이후에도 전략별 새로운 진입 조건을 만족해야 한다.

같은 급락 후보나 동일한 반등 사건을 재사용해 주문을 반복 발생시키지 않는다.

후보 ID 또는 Episode ID를 관리한다.

# 10. 실시간 스크리닝 연동

기존 실시간 스크리닝 기능을 유지한다.

스크리닝은 전체 감시 종목 중 선택된 단일 전략의 진입 가능성을 평가한다.

필터는 다음 개념으로 구분한다.

- Universe: 거래할 수 있는 종목인가
- Attention: 현재 시장에서 거래가 집중되는가
- Strategy Signal: 선택된 전략의 진입 조건을 만족하는가
- Risk Approval: 실제 신규 주문을 허용할 수 있는가

이 네 단계를 별도 상태로 기록한다.

당일 거래량 순위 TOP 10 등의 조건을 사용한다면 매매 판단 당시 확인할 수 있었던 순위를 사용한다.

당일 장 종료 후 최종 순위를 과거 오전 시점에 적용해서는 안 된다.

토스나 키움 등에서 제공되는 인기 검색순위는 실제 데이터가 확보되고 발생시점이 확인될 때만 사용한다. 지원되지 않는 랭킹은 다른 지표로 조용히 대체하지 않는다.

선택된 전략에서 사용할 수 없는 데이터 때문에 신호를 생성하지 못하면 그 이유를 기록한다.

스크리닝은 새로운 매수 후보를 차단할 수 있지만, 보유 중인 종목의 보호 청산은 차단해서는 안 된다.

# 11. 데이터 품질 및 백테스트 원칙

## 11.1 미래 데이터 금지

모든 지표는 해당 판단 시각까지 실제 사용 가능했던 데이터만 사용한다.

다음은 금지한다.

- 현재 시점에 확정되지 않은 장중 고가·저가 사용
- 미래의 Pivot High 확정 정보 사용
- 미래의 거래량 순위 사용
- 장 종료 후 확인한 뉴스·공시 정보를 오전 진입 판단에 사용
- 주문을 발생시킨 동일 틱에서 체결이 끝났다고 가정
- 일봉 내부의 고가·저가 발생 순서를 임의로 확정

과거 데이터를 로딩할 때도 각 값의 `KnownAt`을 관리한다.

## 11.2 틱·호가 백테스트

가능하면 실제 체결과 호가 이벤트를 원래 시간 순서로 재생한다.

실제 주문을 전송하지 않으면서 Strategy Engine, Position Engine, Risk Engine에 동일한 이벤트를 전달해야 한다.

리플레이와 실시간 모드의 차이는 데이터 공급과 주문 실행 어댑터에 한정한다.

전략 계산 수식은 동일해야 한다.

## 11.3 체결 모델

매수와 매도에 대해 다음을 반영한다.

- 주문 제출 지연
- 지정가와 시장가 차이
- 매수·매도 호가
- 주문가격 정규화
- 수수료
- 적용 가능한 거래세
- 슬리피지
- 부분체결
- 미체결
- 주문 취소·변경 지연
- 실제 관측된 거래량에 따른 제한적 체결
- 원본 데이터가 지원하지 않는 호가 대기열 정보의 불확실성

특히 호가 틱떼기 전략에서는 매수와 매도 모두 체결됐을 경우에만 왕복 거래의 실현손익을 확정한다.

체결 확인이 없는 잔여 수량은 미체결 또는 보유 상태로 남겨야 한다.

## 11.4 미국주식 특성

장전, 정규장, 장후 거래 세션을 구분한다.

미국 동부 시간대와 서머타임을 처리한다.

거래시간별 주문 가능 유형, 호가 신뢰도, 유동성이 다르므로 데이터 공급자가 지원하지 않는 거래 세션은 주문 가능하다고 가정하지 않는다.

주식병합, 액면분할, 거래정지, LULD 변동성 중단 등 가격 해석에 중요한 사건은 데이터에 반영하거나 미확인 상태로 차단한다.

## 11.5 백테스트 지표

다음 결과를 계산한다.

- 총 매매 횟수
- 총 실현손익
- 순수익률
- 승률
- 평균 이익
- 평균 손실
- 손익비
- Profit Factor
- Expectancy
- 최대 낙폭(MDD)
- 평균 보유시간
- 평균 슬리피지
- 주문 체결률
- 부분체결률
- 미체결·취소 비율
- 전략별 진입 신호 발생 횟수
- 필터별 진입 거절 횟수

실현손익:

`RealizedPnL = Sum(SellFillValue) - Sum(AllocatedBuyCost) - Fees - Taxes`

승률은 전량 청산이 완료된 거래를 기준으로 계산한다.

기대값:

`Expectancy = WinRate × AverageWin - LossRate × AverageLossAbsolute`

Profit Factor:

`ProfitFactor = GrossProfit / GrossLossAbsolute`

손실 거래가 0건일 때는 0으로 나누지 않고 별도 상태로 표시한다.

미청산 포지션은 평가손익으로 구분하며 확정된 승리 거래로 계산하지 않는다.

성과에는 지정가 체결 가정과 데이터 품질 정보를 함께 보존한다.

# 12. 전략 설정 데이터 구조

기존 전략 설정의 저장 기능을 유지하면서 새로운 버전의 전략 정의를 저장할 수 있게 한다.

권장 개념 구조:

`InjesStrategyDefinition`

포함 필드:

- SchemaVersion
- StrategyId
- StrategyName
- StrategyMode
- CommonParameters
- StrategyParameters
- EffectiveAdvancedParameters
- ExecutionPolicy
- CreatedAt
- UpdatedAt

전략별 파라미터는 독립적인 타입으로 구현한다.

예시:

- `MomentumPullbackParameters`
- `QuoteScalpingParameters`
- `CrashReboundParameters`
- `SupportZoneParameters`

공통 타입:

- `InjesCommonParameters`
- `ParameterDefinition`
- `StrategySignal`
- `StrategyContext`
- `StrategyState`
- `StrategyEvaluationResult`

전략의 파라미터 설정을 저장·복구·JSON 내보내기·불러오기 했을 때 값과 의미가 보존되어야 한다.

지원하지 않는 StrategyId, 잘못된 Enum, 범위를 벗어난 수치, 존재하지 않는 파라미터명, 중복 JSON 키는 명시적 오류로 처리한다.

지원하지 않는 전략을 다른 전략으로 자동 변환해서 실행하지 않는다.

이전 전략 설정을 새로운 형식으로 옮길 수 없다면 기존 설정을 보존하고 명시적으로 호환 불가 상태를 기록한다.

# 13. 확장성 요구사항

신규 전략을 추가할 때 다음 항목만 구현하도록 설계한다.

1. 고유 StrategyId
2. 전략 전용 파라미터
3. 파라미터 검증 및 메타데이터
4. 필요한 데이터·지표 선언
5. 진입 신호 계산
6. 전략 고유 청산·무효화 계산
7. Standard 파라미터 변환 규칙
8. 단위 테스트

기존 전략 엔진에 StrategyId에 따른 거대한 if/else 분기문을 계속 추가하는 방식은 피한다.

`IStrategyDefinition`, `IStrategyRuntime`, `IStrategyFactory` 또는 동등한 인터페이스를 통해 전략을 등록할 수 있도록 한다.

전략별 런타임 상태는 종목별·실행 인스턴스별로 분리한다.

전략을 교체할 때 기존 전략의 저점, 최고가, 반등 후보, 거래량 기준, 주문 의도가 새로운 전략에 이어지면 안 된다.

새 전략이 등록되어도 기존 전략의 저장 파일 형식과 계산 결과가 의도치 않게 변하지 않아야 한다.

# 14. 반드시 수행할 테스트

다음 상황을 자동 테스트에 포함한다.

**공통 엔진**

- 한 세션에 하나의 전략만 실행되는지
- 다른 전략이 신호나 주문을 생성하지 않는지
- 설정 저장·복구 후 동일한 파라미터를 사용하는지
- Standard 변환과 Advanced 직접 설정이 정확히 반영되는지
- 데이터 부족 시 잘못된 진입이 발생하지 않는지
- 동일 틱의 중복 수신에서 신호가 중복 발생하지 않는지
- 실제 매수 체결 전 Holding 상태로 전환되지 않는지
- 부분체결 시 수량과 평균 매수가가 올바른지
- 주문 취소 요청 중 재주문이 중복 발생하지 않는지
- 보유 중 신규 진입 스크리너가 거절되어도 손절이 실행되는지
- 계좌 손실한도 도달 이후 신규 매수가 차단되는지

**급등주 눌림목**

- +10% 상승 후 -3% 눌림 감지
- 저점 갱신 시 60초 안정시간 초기화
- 60초 안정 후 실제 반등 상향돌파
- 거래량 재유입 부족 시 진입 거절
- 이미 발생한 반등을 중복 매수하지 않음
- 고점과 저점 계산에 미래 틱을 사용하지 않음

**호가 틱떼기**

- 체결빈도 및 호가변경 조건 적용
- 유효하지 않은 Bid/Ask 차단
- 스프레드가 거래비용보다 작으면 진입 거절
- 매수호가에 지정가 주문을 냈다는 이유만으로 체결되지 않음
- 매수 체결 후 실제 수량만큼 매도 주문
- 부분체결과 주문 취소 처리
- 유동성 감소에 따른 청산
- 주문가격과 실제 체결가격 차이 기록

**폭락주 반등**

- -50% 급락 기준가격 선택
- 저점 안정시간 검증
- 추가 저점 갱신 시 후보 상태 재설정
- 반등 조건 충족 후 진입
- 저점 재이탈 시 후보 무효화
- 공시 위험 또는 위험 정보 미확인 시 차단
- 60초 최대 보유시간 검증

**지지구간 반등**

- 확정된 Pivot High만 사용
- MA 계산에 미완성 미래 봉을 사용하지 않음
- 매물대 거래량이 중복 배분되지 않음
- 지지선 병합 및 Cluster 경계 계산
- 최소 2개 독립 지지 근거 확인
- 지지구간 접근 판단
- 반등 확인 ON/OFF 적용
- 지지구간 하단 이탈 시 청산

추가로 실시간 이벤트와 동일한 과거 틱 데이터를 리플레이했을 때 결정론적으로 같은 신호 순서가 생성되는지 검사한다.

단, 데이터 도착 순서, 실행 어댑터, 체결 모델이 다르면 실제 체결 결과까지 같다고 가정하지 않는다.

## 16. 완료 조건

다음 조건을 모두 충족해야 작업 완료로 판단한다.

- Inje's Strategy라는 새로운 전략 체계가 존재한다.
- 네 전략을 각각 독립적으로 선택하고 실행할 수 있다.
- 한 번에 한 전략만 실제 매수 신호를 생성한다.
- 모든 파라미터가 검증되고 저장·복구된다.
- 각 전략의 수식과 상태 전이가 테스트된다.
- 실시간 틱과 과거 데이터 리플레이에 같은 전략 판단 로직이 사용된다.
- 공통 손절·익절·시간청산·위험 관리가 정상 작동한다.
- 주문 상태와 체결 상태가 분리되어 있다.
- 기존 UI 레이아웃이 유지된다.
- 기존 프로그램의 비전략 기능이 유지된다.
- Windows WPF 및 macOS Avalonia의 관련 빌드·테스트가 통과한다.
- 실제 주문 기능은 별도의 명시적 승인 없이 활성화되지 않는다.

## 17. Codex 작업 시 주의사항

현재 저장소의 최신 소스와 `AGENTS.md`, `HANDOFF.md`를 먼저 확인한다.
