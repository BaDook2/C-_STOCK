# 키움 REST API

## 실시간 준비 봉 최소 조회 (2026-11-06)

`IRecentMinuteIntervalHistoryBroker.RecentMinuteHistory`는 ka10080의 `tic_scope`에 지원 분 간격을 전달하고, 필요한 고유 시각 봉 수를 확보하면 연속 조회를 종료한다. `RealtimeWarmup.RequiredBars`는 활성 지표의 최대 준비 기간(MA999 포함)을 계산한다. 시간봉·합성 분봉은 지정 간격을 정확히 나누는 최대 native 간격을 사용한다. 예를 들어 1/2시간봉은 60분 원본, 7분봉은 1분 원본이다. 연구 기간 전체 조회와 기존 차트 조회는 그대로 두고 실시간 준비에만 적용한다.

최근 준비 봉은 종목·지정봉·증권사·필요봉 수 기준 2분 제한 캐시를 사용한다. API의 650ms 요청 제한은 유지한다. 하루 전체 길이와 장 끝의 짧은 잔여 구간을 고려해 필요한 원본 봉 수를 계산한다. 15:00~15:30 구간을 완성된 1시간봉으로 사용하지 않는다. 공통 `FromMinutes` 집계는 원본 간격을 받아 연속 구간과 완전한 길이를 확인하므로 60분 원본을 2/3/4/6시간봉으로 묶을 수 있다. 원본 거래대금이 없으므로 OHLC 평균×거래량 추정 표시는 유지하며 정확한 체결대금으로 간주하지 않는다.

## 목적과 인증
국내·미국 실제 계좌 직접 주문과 잔고·주문 상태 조회. App Key / Secret을 사용자 입력창에서 받아 인증·계좌 조회 성공 후 Windows DPAPI CurrentUser로 암호화해 저장한다. 등록 IP와 실전 계좌용 키가 필요하다. 인증 POST /oauth2/token (au10001), 연결 계좌 ka00001. 운영 https://api.kiwoom.com, 이전 모의 테스트 호스트 https://mockapi.kiwoom.com.

## 호출과 오류
REST 요청은 앱에서 직렬화하고 최소 650ms 간격을 둔다. 이는 앱의 보수적 간격이며 증권사의 모든 상품·계정별 제한을 보장하지 않는다. 토큰 만료 전 갱신하며 주문 POST는 자동 재시도하지 않는다. 타임아웃·형식 오류·응답 유실은 Unknown 처리한다. 비밀 키/토큰/원문 응답을 로그에 남기지 않는다.

## 차트 이력과 WebSocket
국내 분봉은 `ka10080`을 사용한다. 앱이 확인한 직접 지원 간격은 1·3·5·10·15·30·45·60분이며 `IRangedMinuteIntervalHistoryBroker`가 `tic_scope`에 해당 값을 넣는다. 1시간봉 스크리닝은 공식 60분봉을 직접 사용해 같은 기간의 1분봉 수십 배를 내려받는 일을 피한다. 직접 지원하지 않는 임의 간격만 1분봉을 받아 앱에서 집계한다. 국내 틱은 `ka10079`의 1틱 이력을 받아 N틱봉으로 집계한다. 응답의 부호 있는 가격은 절대 가격으로 정규화하고 시간순으로 정렬한다. 같은 시각의 틱은 증권사 응답 순서를 보존해 순서를 임의로 바꾸지 않는다. 두 기능은 국내 KRX 종목만 지원하며, 호환 API가 없는 계좌나 오프라인 상태에서는 해당 선택기를 비활성화한다.

차트 이력은 최근 화면을 빠르게 여는 용도이므로 `cont-yn=Y`가 계속 오더라도 최대 3페이지를 합쳐 반환한다. 이는 잔고·주문 내역의 완전조회와 별도 정책이다. 기존에는 공통 100페이지 한도까지 650ms 간격으로 순회해 약 1분 후 전체 결과를 버릴 수 있었지만, 차트는 받은 3페이지를 정상 자료로 사용한다. UI는 틱·분봉 요청을 15초로 제한하고 `CancellationToken`을 HTTP 전송까지 전달한다. 긴급중지 시 진행 중인 차트 요청을 취소한다.

기존 `KiwoomMarketDataProvider`는 `/api/dostk/websocket`, `/api/us/websocket`의 LOGIN, REG, REMOVE, PING, REAL을 지원한다. 국내 0B/0D, 미국 FE/FT다. 틱 차트는 REST 이력을 먼저 표시하고 실시간 키움 연결이면 이후 관측 체결을 같은 화면 끝에 이어 붙인다.

## 관련 코드와 검증
KiwoomBroker.cs, RemoteTradingSession.cs, OrderGuard.cs, MarketData.cs. 공식 명세 사본 docs/kiwoom-api-spec.json. `ka10079`/`ka10080`의 요청 헤더·본문·응답 파싱은 가짜 HTTP 핸들러로 검증했다. 실제 계좌 인증은 아래와 같이 읽기 전용으로 확인했으며 장중 이력·체결 및 외부 주문 실행 검증은 수행하지 않았다.

## 실전 키와 실제 틱
온라인 진입은 실전 호스트의 토큰·계좌 검증 뒤에만 허용한다. 인증 거부와 통신 장애를 구분해 안내하며 실패 시 오프라인으로 복귀한다. 실제 키를 사용한 WebSocket·체결·주문은 실행하지 않았다.
실전 틱: wss://api.kiwoom.com:10000/api/dostk/websocket, 미국은 /api/us/websocket. 기존 모의 호스트 기본값을 보존하고 live:true로 명시한 연결만 실전 호스트를 사용한다. 공급자 시각 해석·누락·호가 권한의 제한은 기존 품질 검사를 따른다. 등록 키가 없으면 공개 일봉 및 저장된 실제 틱만 이용 가능하다.

## 2026-11-04 읽기 전용 연결 진단

사용자 PC의 저장된 실전 키를 출력하지 않고 운영 서버에 인증·계좌·잔고 조회만 수행했다. `KRX` 연결은 세 단계 모두 성공했다. 같은 키의 `NASDAQ` 연결은 인증과 계좌 조회가 성공했고 `ust21070` 해외 잔고 단계에서 서버 오류 코드 2가 발생했다. 이것만으로 키 자체가 잘못됐다고 판단하지 않는다. 해외주식 API 권한·계좌 설정 등 서버 측 사유는 계좌에서 확인해야 한다. 키 설정 초기 검증은 차트가 미국 종목이어도 국내 계좌 경로를 사용하고, 해외 주문 단계의 잔고 거부는 별도 안내하며 실제 주문을 차단한다. 실제 주문/WebSocket 검사는 수행하지 않았다.

## 2026-11-07 분봉 조회 경계
