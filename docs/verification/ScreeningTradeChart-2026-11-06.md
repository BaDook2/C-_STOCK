# 스크리닝 지정봉 체결·표식 선택 검증 — 2026-11-06

## 원인과 변경

- 일반 스크리닝 상세의 일봉 경로만 공통 백테스트를 호출했다. 분·시간봉 경로는 봉과 저장된 과거 체결만 읽어, 저장 체결이 없으면 BUY/SELL이 나오지 않았다. `ScreeningNavigation.LoadScreeningChart`에서 같은 `IOversoldBacktestService`를 호출하도록 연결했다.
- 활성 지표의 준비 봉은 `RealtimeWarmup.BacktestHistoryStart`로 계산하고 종목/차트 백테스트도 이 정책을 공유한다. 화면은 스크리닝 당시 시작~종료일만 표시하며, 실제 신호/체결은 당시 설정·사실과 다음 완성봉 시가 규칙을 따른다. 모형체결을 실제 주문으로 저장하거나 전송하지 않는다.
- 25봉 이하에서는 우클릭해도 표시 범위가 같았지만 입력 잠금만 풀렸다. 이제 해당 자료는 처음부터 휠/드래그가 가능하다. 큰 자료는 기존 전체/확대 탐색 구조와 최대 축소 한도를 유지한다.
- 기존 클릭은 포인터 아래 봉에 체결이 있어야 했다. 글자가 옆 봉까지 뻗거나 묶음의 중심이 체결 봉 사이이면 클릭을 놓쳤다. 실제 렌더한 글자·배지의 영역을 먼저 검사하고 기존 체결 봉 클릭도 유지한다. 이동/확대/크기/원본 변경 뒤 오래된 화면 영역은 사용하지 않는다.
- 거래 선택은 `ScreeningChartViewModel.SelectedTrade`와 표의 `SelectedItem`을 연결한다. 실제 시간·방향·수량·가격을 비교하고 출처·거래 번호·사유를 우선해 선택한다. 인접한 시각의 다른 거래로 대체하지 않는다. 표식 클릭은 선택/스크롤/상세만 바꾸고 차트 범위는 유지한다.
- 오른쪽 끝의 개별 표식은 실제 글자 폭을 고려해 안쪽에 배치한다.

## 실제 Windows 마우스 확인

`Stock.Tests.exe --screening-trade-demo artifacts/screening-fill-native`는 격리 DB/가짜 증권사/명시된 검증 종목만 사용한다. computer-use 스킬의 `@oai/sky`로 해당 검증 창만 조작했다.

1. 최초1시간봉6개, `Locked=false`를 확인했다. 우클릭 없이 매수 글자 한 번 클릭 → 12:00 매수 행과 지지 snapshot이 선택됐다.
2. 매도 글자 한 번 클릭 → 14:00 TP1 행과 익절 상세가 선택됐다.
3. 우클릭 없이 휠 확대 →6개에서5개. 선택된 매도 행은 유지됐다.
4. 단위를1분으로 바꿈 → 전체360봉/표식2개 유지. 전체 범위 상태의 매수 묶음 글자를 클릭해12:00 매수 행이 선택됐고 차트 범위360개는 유지됐다.
5. 모든 단계 실제 주문 호출0회. 검증 창은 정상 종료했다. 근거 `artifacts/screening-fill-native/{hour-wheel,minute-badge-selection}.json`, 자동 렌더 이미지 `artifacts/screening-fill-final/screening-fills-{Minute,Hour}.png`.

실제 키·실계좌 주문이나 사용자 DB 수리는 실행하지 않았다. 체결이 없는 전략 결과에 표식을 생성하지 않으며, 제공자가 반환하지 않는 분봉은 다른 봉으로 가장하지 않는다.
