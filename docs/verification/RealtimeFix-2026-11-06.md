# 실시간 스크리닝 종료·속도·선별 수정 (2026-11-06)

## 종료 원인과 처리

Windows Application/.NET Runtime의 09:18:49, 09:20:15 기록에서 `SqliteException`, SQLite 오류 11 (`database disk image is malformed`)이 `TradingStore.States → LoadRealtimeScreeningChart → OpenRealtimeScreeningStock → ScreeningRowDoubleClick` 경로로 빠져나가 WPF 프로세스를 종료한 것을 확인했다.

ASCII namespace 조회는 state 기본키 BINARY 범위 인덱스를 사용한다. 체결 namespace만 읽으며 과거 백테스트/자료 캐시 전체를 훑지 않는다. SQLite 체결 조회 장애는 `ChartTradeHistory.Read`에서 격리하고 읽기 실패 안내와 함께 표시 가능한 차트·모형 결과를 유지한다. 실제 체결을 만들어 채우지 않는다. 실시간/일반 차트 진입과 이전·다음 이동의 비동기 예외도 밖으로 전파하지 않는다.

사용자 DB를 read-only 연결로 검사했을 때 prefix 조회 0건, 전체 state 42건 및 `quick_check`는 성공했다. **과거 오류는 확인했지만 현재 지속되는 물리적 손상은 재현하지 못했다.** 원인을 확정하거나 복구 완료라고 주장하지 않는다. 사용자 DB의 삭제·초기화·자동 복구·교체를 수행하지 않았다.

## 전략 선별

선택 대상 전체는 내부에서 계속 감시한다. 기본 표는 공통 `OversoldLiveStrategy.LatestEntryEvaluation`의 활성 비진단 조건 전부 통과, 유효 technical candidate, 신선한 시세, 정규장, 실행 상태 정상인 종목만 표시한다. OFF 조건은 제외하고 자료 미확인/미평가를 성공으로 세지 않는다. 단순 상위 목록·과거 잔존 매수 신호·접근도 100점만으로 편입하지 않는다.

`전체 대상·미충족 사유 보기`로 전체 내부 대상과 준비 실패를 볼 수 있다. 검사/분석/전략 일치/자료 미확인 수는 별도로 표시한다. 조건을 벗어나면 표에서는 제거하되 계속 감시하여 조건이 다시 충족되면 편입한다. 실제 주문/체결은 별도이며 계좌·위험 검사와 중복 주문 방지를 유지한다.
