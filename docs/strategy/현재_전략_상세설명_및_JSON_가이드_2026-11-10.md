# 현재 전략 상세 설명 및 JSON 불러오기 가이드

작성·코드 확인: 2026-11-10 · 대상: C-_STOCK의 현재 로컬 Avalonia 개발 소스

이 파일은 ChatGPT에 그대로 첨부해 전략의 동작과 설정을 논의할 수 있는 독립 설명서다. 구현된 규칙, 기본값, 실행 모드의 차이, 전체 JSON 예제를 함께 제공한다. 수익성이 검증된 전략이나 최적화된 추천값을 의미하지 않는다.

**여기에 적힌 수치는 코드 기본값이다. 사용자가 앱에서 현재 선택했거나 저장하지 않은 개인 설정을 추출한 결과가 아니다. 개인 설정으로 논의하려면 앱의 ‘내보내기’로 만든 JSON도 이 문서와 함께 첨부하면 된다.** 사용자 DB·계좌·API 키는 이번 확인에서 읽지 않았다.

## 1. 가장 먼저 알아야 할 구조

현재 전략은 ‘급락 판단 전략 → 사용’ 체크에 따라 두 엔진 중 하나를 선택한다.

| 사용 체크 | 실제 진입·추가매수·청산 엔진 | 기술적 숫자를 읽는 곳 |
|---|---|---|
| OFF (`configuration.useCrashStrategy: false`) | 기존 과매도·지지군집 반등 전략 | 바깥 `configuration` |
| ON (`true`) | 급락 판단 전략 D의 전체 규칙 | `configuration.crashStrategy.configuration`와 `configuration.crashStrategy.dayTrading` |

ON은 기존 전략에 급락 필터 하나를 추가한다는 뜻이 아니다. 사용자가 정한 방식대로 **D의 진입·청산 전체 규칙을 사용한다.** 바깥의 기술적 조건과 D의 기술적 조건은 별도로 저장된다. 따라서 바깥 RSI를 바꾸는 것과 D 내부 RSI를 바꾸는 것은 다르다.

다만 다음 5개 값은 바깥 설정이 공통 원본이다. 편집기에서 현재값을 만들거나 실제 D 실행 정의를 만들 때 D 내부의 중복 값을 이 값으로 맞춘다.

- `initialCapital`: 백테스트 초기 현금
- `plannedInvestment`: 총 투자금
- `commissionPercent`: 편도 수수료
- `taxPercent`: 매도 거래세 가정
- `slippagePercent`: 체결 슬리피지 가정

D 내부의 중복 투자금·비용을 JSON에서 다르게 입력해도 독립 비용으로 실행하지 않는다. 전체 예제에서는 양쪽 값을 같게 넣었다. D 안에 보이는 주문당 금액·총 노출·손절 위험예산은 이 공유 투자금과 별도로 함께 적용되는 한도다.

화면의 배치는 `백테스트 전용 → 급락 판단 전략 → 공통 전략 조건`이다. ‘시점별 검증 자료(고급)’와 수동 종목상태·위험·시장세션 JSON 입력창은 제거했다. 내부 엔진은 여전히 당시 거래 가능 여부·위험·시장 세션 자료를 확인한다. 화면을 없앤 것이 해당 확인을 생략한다는 뜻은 아니다.

## 2. 기간·자료·차트의 관계

### 2.1 온라인 판단과 봉 단위

온라인에서 각 지표의 기간은 그 지표 옆의 단위를 따른다. 차트에 표시하는 봉 기준과 전략 판단 자료를 분리한다. 일반 기간은 분·시간·일봉·주봉·월봉, 이동평균 기간은 일봉·주봉·월봉을 사용한다. 필요한 해당 단위의 확정봉이 준비되어야 조건을 계산할 수 있다. 단위를 바꿨다고 없는 분봉이나 거래량 자료가 만들어지지 않는다.

예를 들어 `rsiPeriod: 14`와 `parameterTimeframes.RsiPeriod: {size:1,unit:3}`은 **1시간봉 14개 기준 RSI**다. `rsiPeriod:14` 자체가 14시간이라는 단독 시간 지정은 아니다. JSON으로 `{size:3,unit:3}`을 가져오면 3시간봉 14개다. 화면에서 같은 단위를 유지하면 이 크기를 보존하며, 다른 단위로 새로 선택하면 크기는 1부터 시작한다.

일봉·주봉·월봉의 `size`는 1이어야 한다. 기간 길이는 RSI 기간, 이동평균 기간 목록 등 별도 숫자로 지정한다. 일봉은 달력의 모든 날짜를 한 번씩 세는 것이 아니라 제공된 거래 세션·확정봉을 따른다. 주봉·월봉도 그 시점에 완성된 자료만 사용한다.

### 2.2 오프라인 백테스트·스크리닝

오프라인 연구는 일봉 자료 기준이다. 온라인용 분·시간·주·월 설정을 저장해 둘 수 있으나 오프라인 실행 시 일봉 기준을 사용한다. D 연구에서는 지표별 override를 비우고 기본 분석·이동평균·매물대 자료를 일봉으로 맞춘 실행 사본을 만든다. 저장한 원본 설정은 유지된다.

D 기본값은 당일 청산 ON, 15:00 신규 진입 종료, 15:10 청산 요청이다. 일봉 종가만으로 장중 진입·청산 시각이나 같은 날의 새 반등을 재현할 수 없으므로 기본값 그대로의 일봉 연구에서 거래 0건이 나올 수 있다. `dayOnly:false`인 일봉 연구는 종가 판단과 다음 봉 시가 체결 가정을 사용하며 장중 전략과 같은 결과라고 해석하면 안 된다.

### 2.3 가격자료 검증 모드와 자료 부족

`configuration.usePriceOnlyBacktest`는 연구에서 미확인 종목 상태·위험을 일반주식·거래가능·위험없음으로 가정하는 명시적 옵션이다. 기본 OFF다. 미래 정보나 실제 체결을 만들지 않으며 스크리닝·실계좌 승인으로 전이하지 않는다. 기존 전략은 이 모드에서 최소 거래대금을0으로 정한 경우에만 실제 거래대금 부족 검사를 우회할 수 있다. D의 연구가정은 상태·위험을 보충하는 것이며 실제 거래대금 평균 자료까지 만들어 주지 않는다.

기본값으로 거래가0건이면 자료 미확인·MA/매물대 준비 부족·필터 미충족·당일 운용 시각을 각각 확인해야 한다. JSON이 정상적으로 읽혔다는 사실과 전략이 그 자료에서 매수할 수 있다는 사실은 별개다. 기존 엔진의 해외 일봉은 가격자료 검증 모드에서 연구용으로만 지원하며 금액 단위는USD다. 아래 원화 예제는 국내 종목 기준이고 D는 국내 일반주식 전용이다.

### 2.4 차트 표시

- 검은 240일선은 실제 일봉 종가의 MA240 표시다. 차트를 분봉으로 보더라도 자동으로 240분선으로 바뀌지 않는다.
- D 매수에 실제 사용된 반등 저점은 보라색 가로선과 ‘급락 판단 지점’으로 표시한다. 단순히 낙폭이 가장 컸던 모든 저점을 뜻하지 않는다.
- 차트 선과 매수·매도 표시는 계산·신호·체결 기록을 시각화한 것이다. 보라색 선 자체가 추가 매수 조건은 아니다.
- 화면 가격은 정수로 내려 표시하지만 계산·체결 가격의 원래 정밀도는 유지한다. 불필요한 `.00`을 입력창에서 제거한 것과 실제 소수 수수료·비율 허용은 별개다. `0.015`, `0.5`, `0.7` 등 의미 있는 소수는 사용한다.

## 3. 공통 계산식

하락률과 반등률은 다음처럼 계산한다. `%` 값에는 100을 나누기 전의 백분율 숫자를 넣는다.

```text
고점 대비 하락률 = (판단가격 / 구간 최고 HIGH - 1) × 100
저점 대비 반등률 = (판단가격 / 접근 후 저점 - 1) × 100
지지 이탈선 = 진입 당시 고정한 지지 하단 × (1 + supportBreakPercent / 100)
비상 손절선 = 실제 평균 매수가 × (1 + emergencyStopLossPercent / 100)
익절 목표 = 실제 평균 매수가 × (1 + takeProfitPercent / 100)
추적 손절선 = 이전까지 관측한 최고가 × (1 - trailingStopPercent / 100)
추가매수 기준 = 직전 실제 매수가 × (1 + additionalEntryDropPercent / 100)
```

예를 들어 낙폭 `-20`은 -20%, 반등 `0.5`는 +0.5%, 수수료 `0.015`는 체결금액의 0.015%다. 수수료 1.5%를 뜻하지 않는다. 일봉의 HIGH·LOW가 있다는 이유로 그 안에서 먼저 발생한 가격 순서를 알 수 있는 것은 아니다.

RSI는 처음 N개 종가 변화의 평균 상승·하락을 구한 다음 Wilder 방식으로 순차 갱신한다. RSI N에는 최소 N+1개의 종가가 필요하다. 평균 상승과 하락이 모두 0이면 50, 평균 하락만 0이면 100이다. 거래량 배수는 현재 확정봉 거래량을 현재 봉을 제외한 이전 N봉 평균 거래량으로 나눈다. 평균이 0이거나 자료가 부족하면 준비되지 않은 조건으로 처리한다.

## 4. 기존 전략: 급락 판단 전략 사용 OFF

### 4.1 최초 매수 후보를 만드는 순서

1. 그 시점의 일반주식·시장·거래정지·관리 상태를 확인한다. 기본적으로 국내 코스피·코스닥 일반주식이 대상이다. ETF·ETN·SPAC 등 제외 상품과 미확인 자료를 구분한다.
2. 선택한 단위의 이전 N봉 실제 거래대금 평균이 최소 거래대금 이상인지 확인한다. 종가×거래량을 실제 거래대금으로 대체하지 않는다.
3. 중기 낙폭 또는 단기 낙폭 중 하나 이상을 충족해야 한다. 각 구간의 최고 HIGH와 현재 확정 CLOSE를 비교한다. 기본은 최근 20봉 고점 대비 -20% 이하 **또는** 최근 3봉 고점 대비 -15% 이하다.
4. RSI 사용 시 RSI ≤ 최대 RSI, 거래량 조건 사용 시 현재 거래량/이전 평균 ≥ 거래량 증가 기준을 함께 요구한다. 기본은 RSI14 ≤ 30, 거래량20봉 평균의 2배 이상이다.
5. 당시 위험 정보가 위험 없음으로 확인되어야 한다.
6. 활성 지지 후보들을 군집화한 뒤 최소 지지 개수 이상이 겹친 군집에 현재 종가가 접근했는지 확인한다. 기본 최소 개수는 2개, 접근 허용 폭은 군집 하단·상단의 ±3%다. 접근한 군집 중 현재가와 중심이 가까운 것을 우선한다.
7. 이전 전량 청산이 있다면 더 낮은 새 군집 거리와 재진입 대기기간을 확인한다.
8. 반등 확인이 켜져 있으면 유효 접근 후 추적한 저점에서 지정 비율 이상 반등한 확정 종가를 기다린다. 기본 OFF이므로 유효 접근 자체로 신호가 가능하다.

표시 전용 ‘근접 후보’는 활성 조건의 접근도가 최소 점수 이상인 연구 후보도 보여 주는 기능이다. 확률·승률·주문 승인 점수가 아니다. 스크리닝에서 후보를 찾은 것과 매수 주문·체결은 구분된다.

### 4.2 지지 후보와 군집

| 종류 | 계산·사용 가능 시점 |
|---|---|
| 이동평균 | 선택한 기간의 확정 종가 단순평균. 기본 기간 목록 120,240,480,999. 준비 자료가 부족한 기간은 개별 제외한다. |
| 확정 과거 고점 | 중심 HIGH가 왼쪽 N개·오른쪽 M개 HIGH보다 모두 엄격히 높아야 한다. 기본 좌20·우20. 오른쪽 봉이 도착한 뒤부터 사용한다. |
| 근사 매물대 | 최근 240봉의 각 LOW~HIGH가 차지하는 가격 bin에 그 봉 거래량을 균등 배분한다. 실제 체결가별 거래량은 아니다. |

근사 매물대의 최소 bin 폭은 기본 100원이다. 가격 범위·호가·최대 512bin 제한에 따라 실제 폭이 커질 수 있다. 최대 bin 거래량의 70% 이상인 bin을 선택하고 기본 1% 병합 거리 이내를 합친다. 중심은 bin 중간가격을 거래량으로 가중한 값이다.

지지 후보는 ID 중복을 제거하고 대표가격 순으로 정렬한다. 이웃한 두 대표가격 차이가 왼쪽 가격 대비 군집 범위(기본5%) 이내이면 같은 군집으로 연결한다. 연결식이므로 최종 군집의 전체 폭이 반드시 5% 이내인 것은 아니다. 군집 하단은 후보 하단의 최솟값, 상단은 최댓값, 중심은 후보 중심의 단순평균이다. 최소 개수는 독립 후보 개수이며 매물대 내부 bin 개수가 아니다. MA와 고점만으로도 개수를 채울 수 있어 세 지지 유형을 각각 필수로 요구하는 구조는 아니다.

### 4.3 접근 이후의 저점과 재설정

최초 유효 군집 접근 때 저점은 그 봉의 종가에서 시작한다. 그 이후 관측 봉의 LOW로 저점을 낮춘다. 최초 접근 이전의 같은 봉 LOW를 소급해 ‘접근 후 저점’으로 쓰지 않는다. 군집 구성 ID가 달라지거나 중심 변화가 허용치(기본5%)를 넘거나 후보 유지기간(기본20시장 거래일)이 지나면 새 후보로 시작한다.

기존 전략의 반등 확인은 현재 종가가 `저점×(1+반등%)` 이상인지 확인한다. 아래 D처럼 매 관측의 ‘새 상향 돌파’ 사건을 별도로 요구하는 규칙과 차이가 있다.

### 4.4 분할매수·청산

총 투자금 기본 100만원에 최대 3회, 비율 `40,30,30`을 적용한다. 1회 신호당 예산은 총 투자금×해당 비율이다. 수수료와 사용 가능 현금을 고려해 1주 단위로 내림한다. 0주면 실제 진입 횟수를 늘리지 않는다. 추가매수는 직전 실제 매수가 대비 -5% 이하, 필요 시 새 유효 지지 접근, 당시 종목 상태·위험을 확인한다. 익절이 시작된 뒤에는 추가매수하지 않는다.

보유 중 청산 판단의 우선순위는 다음과 같다.

1. 최초 매수 신호의 지지 하단에서 기본 -3% 이탈: 항상 종가로 판단한다.
2. 평균 실제 매수가 대비 기본 -15% 비상 손절: 사용 ON일 때.
3. 이전까지의 최고가에서 기본 7% 추적 손절: 사용 ON 및 시작 조건 충족 시.
4. 기본 20시장 거래일 최대 보유기간.
5. 위 전량 청산 사유가 없을 때 +10% 1차 익절, +20% 2차 익절을 판단한다. 각각 기준 수량의 30%다.

고저가 감지 정책은 당일 LOW로 비상·추적 손절, HIGH로 익절 목표 도달을 감지하되 손절을 먼저 처리한다. CloseOnly는 종가로 감지한다. 당일 HIGH를 먼저 최고가에 넣어 같은 봉의 과거 LOW에 새 추적선을 소급하지 않는다. 추적 손절 기본 시작은 1차 익절의 실제 체결 뒤다.

첫 익절 실제 체결 때까지의 최대 포지션 수량을 익절 비율의 고정 기준으로 삼는다. 남은 수량의 30%를 반복 계산하는 방식이 아니다. 정수 내림으로 0주인 익절 단계가 생길 수 있다. 잔여분은 추적·보유기간 등 청산 조건으로 관리한다.

일봉 신호는 다음 거래 가능한 시가에서 모형 체결한다. 매수 시가는 슬리피지만큼 올리고 매도 시가는 낮춘다. 수수료는 양방향, 거래세는 매도에만 적용한다. 신호 당일 종가를 이미 체결한 가격으로 쓰지 않는다. 기간 마지막 신호를 위한 다음 시가가 없으면 임의 청산 체결을 만들지 않는다.

전량 청산 후에는 이전 진입 군집 중심보다 기본5% 이상 낮은 새 군집이 필요하다. 재진입 대기 기본5시장 거래일, 조기 재진입 옵션은 이 낮은 새 군집이 있을 때 대기기간만 생략한다.

## 5. 급락 판단 전략 D: 사용 ON

### 5.1 D 기본값과 의도

D는 ‘급락 관측 → MA와 매물대가 겹치는 구간 접근 → 그 뒤 실제 관측한 저점 → 새로운 반등 상향 통과’를 추적한다. 국내 일반주식이 대상이며 기본은 1분 분석봉, 신호 평가는 새 체결마다다. MA는 기본 전일까지 확정된 일봉 MA240, 매물대는 기본 일봉240개 OHLCV 근사 자료다. 기본 분석봉을 분봉으로 바꿔도 MA가 자동으로 분봉 MA240이 되지 않는다.

D 내부 RSI·거래량 필터는 기본 OFF, 새 반등 확인은 필수이며 기본 0.5%다. 기본 1회 매수·100% 비중, 비상 손절 -1%, 1차 익절 +1%, 2차 익절 +2%, 각각 30%, 추적폭0.7%·1차 익절 후 시작이다. 이는 실험용 코드 기본값이며 사용자의 저장 전략이나 수익성 검증 결과가 아니다.

### 5.2 급락 이벤트

| 묶음 | 기본 활성 규칙 | 기본 결합 |
|---|---|---|
| 최근 기간 급락 | 중기20봉 고점 대비 -20%, 단기3봉 고점 대비 -15% | OR (`Any`) |
| 장중 급락 | 관측한 당일 고점 대비 -4%, 최근30분 고점 대비 -2% | OR |
| 기간 급락과 장중 급락 | 위 두 묶음 | OR |

각 규칙·묶음에는 별도 사용 여부가 있다. `Any`는 하나 이상, `All`은 활성 규칙 모두다. 자료 미확인은 false와 구분한다. OR에서 하나가 true이면 통과할 수 있지만, AND는 활성 조건 중 false가 있으면 실패하고 나머지 자료 미확인은 통과로 간주하지 않는다.

기간별 단위 override가 없을 때 최근 N일 낙폭은 이전 N-1거래일 최고 HIGH와 현재까지 관측한 당일 고점 중 큰 값을 기준으로 현재 관측가격을 비교한다. 개별 기간 단위가 지정되어 있으면 그 단위의 확정봉 계산을 사용한다. 장중 고점은 관측 가능한 시점의 가격만 사용하고, 최근 구간은 연속 수신 범위가 확보되어야 계산한다. 기본 급락 이벤트 유지기간은 30분이다.

### 5.3 MA·매물대 중첩과 새 반등

1. MA와 유효 매물대 가격 구간의 거리가 기본0.5% 이내여야 한다. MA가 구간 안이면 거리는0이다. 거리는 떨어진 구간 경계와 MA의 차이를 MA로 나눈 백분율이다.
2. 매물대 폭 `(상단-하단)/중심×100`은 기본2% 이하여야 한다. 근사 매물대는 기본 최근240확정봉 균등배분이며 실제 체결 매물대 선택에는 원본 체결 자료가 필요하다.
3. 지원 구간의 하단은 MA와 매물대 하단 중 낮은 값, 상단은 MA와 매물대 상단 중 높은 값이다. 이전과 물리적으로 겹치는 같은 구간을 우선하고, 현재가와 중심이 가까운 구간을 선택한다.
4. 기본1% 접근 거리 안에 가격이 들어온 뒤부터 반등 후보 저점을 추적한다. 후보 기본 유지기간은15분이다. 물리적 구간·MA기간·시간기준이 달라지거나 중심 변화·만료가 발생하면 새 후보가 된다.
5. 접근 후 관측가격의 최저값으로 저점을 갱신한다. 반등률이 직전 평가에서0.5% 미만이었다가 이번 평가에서0.5% 이상이 되는 **새 상향 통과**가 있어야 한다. 이미 오른 상태에서 뒤늦게 후보를 만든 것만으로 매수하지 않는다.
6. 진입 시 지원 구간에서 기본1.5% 이상 떨어진 추격 가격은 차단한다. 같은 후보의 신호는 한 번만 발생시킨다. 기존 포지션·미체결 매수가 있으면 중복 최초 진입을 막는다.

실제 원본 체결 실행은 관측 체결가격을 저점으로 삼는다. 완성봉 연구는 종가 시점의 반등을 근사하며, 봉 내부의 첫 접근·틱 저점·정확한 상향 돌파 시각을 만들어 내지 않는다. 이 차이는 성과 비교에서 분리해야 한다.

### 5.4 계좌 한도·수량

매수 신호가 있어도 주문 수량은 다음 두 상한 중 작은 값으로 내린다.

```text
현금예산 = min(총 투자금×회차비율, 주문당 한도, 사용 가능 현금, 남은 총 노출 한도)
1주 매수비용 = 기준가격×(1+매수수수료%)
1주 손절위험 = (기준가격-보호손절가) + 매수수수료 + 보호손절가의 매도수수료·거래세
수량 = floor(min(현금예산/1주 매수비용, 종목 위험예산/1주 손절위험))
```

유효한 보호손절가가 현재가보다 낮게 있어야 수량을 산정한다. 기본 주문당100만원·총 노출500만원·하루 손실50만원·종목 손절 위험예산1만원·연속 손절3회 한도가 있다. 보유와 미체결 예약금을 포함해 자금·노출을 확인한다. 추가매수 시 이미 사용한 손절위험을 차감한다. 손절 위험예산은 수량을 제한하는 계산이며 갭·슬리피지까지 포함한 실제 손실 상한 보장이 아니다.

추가매수는 D 내부 최대 횟수와 분할 비율을 따른다. 기본1회라 비활성 상태다. 횟수를 늘리면 직전 실제 체결가 대비 추가 하락, 필요 시 지지 접근, 자료·상태 확인을 사용한다. 최초 진입의 새 반등 규칙을 그대로 반복하는 규칙은 아니다. 익절 시작 뒤에는 추가매수하지 않는다.

### 5.5 청산·당일 운용·반복 진입

보호 청산은 진입 당시 매물대 하단 기반 `SupportStop` → 평균 매수가 기반 `FixedStop` → `TrailingStop` → 1차 익절 후 비용 고려 `BreakEvenStop` 순으로 검사한다. D의 지지 손절 기준은 최초 신호에 저장한 **매물대 하단**이다. 기존 전략의 지지 군집 하단과 구별해야 한다. 여러 보호 조건이 동시에 충족되면 앞선 이유를 사용한다. 당일 청산 요청은 별도 시계 정책에서 우선 처리하고, 당일 운용 OFF의 최대 보유기간 청산도 있다.

익절 방식은 전량 익절, 1·2차 분할 익절, 추적 중심 중 선택한다. 기본 분할 익절이며 목표 기준은 실제 평균 체결가다. 같은 평가에서 TP1과 TP2가 모두 도달해도 D는 주문·확인 체결 상태를 따라 각 단계를 진행한다. 고가·저가가 함께 있는 봉 연구는 보호 손절 우선이며 실제 봉 내부 순서를 보장하지 않는다. 1차 익절 이후 본전 보호를 켜면 남은 매수 수수료와 매도 비용을 반영한 가격을 사용한다. 추적선은 보호 목적상 낮아지지 않도록 이전 하한을 유지한다.

당일 운용 기본 ON은 15:00 이후 새 진입을 막고 15:10부터 소유가 확인된 포지션의 청산을 요청한다. 실제 시장 세션과 시간대를 확인한다. 청산 요청과 체결 완료는 다르다. 장 종료 후 보유가 남으면 미청산·대사 필요 상태를 표시한다.

재진입 기본은 ‘같은 구간의 새 반등 허용’이다. 기본 최소60초, 익절 후60초, 손절 후5분을 기다린다. 대기 뒤에도 새 접근·저점·상향 반등이 필요하다. 다른 모드로는 더 낮은 새 구간만, 방향 무관 새 구간만, 재진입 금지가 있다. 기본 종목10회·전략50회·계좌100회/일 한도다. 신호·주문·체결과 예약 상태를 구분해 중복 진입을 제한한다.

### 5.6 자료 안전과 현재 지원 범위

기본 시세 지연 한도2000ms, 원본 메모리20만 이벤트, 처리 대기4096이벤트다. 거래소 시각·연속 체결·당시 상태와 위험 확인을 기본 요구한다. 체결 누락·역순·미확인·버퍼 초과를 성공 자료로 만들지 않는다. 자료 안전 옵션을 낮춰도 실제 돈 주문 승인이 되지 않는다.

D는 기존 원본 체결 가상 실행·확정봉 연구 경로와 연결되어 있다. **D 실계좌 자동 주문 adapter는 아직 연결하지 않았으며 실계좌 실행을 지원하지 않는다.** 기존 전략과 D가 섞인 실행 배치는 분리해서 시작해야 한다. 공개 근사 실시간 스크리닝 경로에서 D를 기존 전략으로 몰래 대체하지 않는다. 이번 JSON 검증은 실제 증권사·계좌·주문 검증이 아니다.

### 5.7 성과 수치의 의미

최종 평가자산은 현금과 남은 보유분의 평가액을 포함하며 실제 확정 손익만을 뜻하지 않는다. 승률·평균 이익/손실·기대값은 전량 청산된 거래를 기준으로 계산한다. 0원 손익 거래는 승리·패배 어느 쪽에도 넣지 않지만 전체 청산 거래 수에는 포함한다. Profit Factor는 양의 확정손익 합계/음의 확정손익 절댓값 합계다. 손실0·이익양수는 무한대 상태를 구분한다.

최대 낙폭은 관측한 계좌 평가자산의 이전 최고값 대비 하락률 최댓값이다. CAGR은 실제 날짜 차이를 연으로 환산한다. Sharpe는 일별 계좌 수익률에서 연 무위험수익률을 일로 환산해 뺀 뒤 표본 표준편차로 나누고 연율화 거래일 수의 제곱근을 곱한다. D는 거래 세션에 해당하는 일별 자산으로 연율화하고 기본20세션보다 짧으면 CAGR·Sharpe를 표시하지 않는다. D의 최대 낙폭은 관측된 전체 자산 곡선에서 계산한다.

기존 전략의 통계 가정은 바깥 annualRiskFreePercent/annualTradingDays다. 현재 D 보고서는 **D 내부 configuration의 두 값**을 읽으며 바깥과 자동 공유하지 않는다. 이 둘은 D 화면에 별도 입력이 없지만 JSON으로 보존되는 값이다. 전체 예제는 양쪽 모두0%/252일이다. 이 부분은 매매 조건의 공유 자금·비용5개와 구별해야 한다.

### 6.1 바깥 61개 설정

### 6.4 개별 기간과 JSON 전용 지표 override

`configuration.parameterTimeframes`는 바깥 기존 전략의 기간 단위다. `configuration.crashStrategy.configuration.parameterTimeframes`는 D 내부 기간 단위다. 사전의 키는 아래처럼 **C# 속성의 PascalCase 이름**을 사용한다. 현재 importer는 대소문자를 정규화하지만 철자가 다른 이름은 오류로 처리한다.

| 사전 키 | 의미 |
|---|---|
| AverageTradingValueLookbackDays | 평균 거래대금 기간 단위 |
| CrashLookbackDays | 중기 낙폭 기간 단위 |
| ShortCrashLookbackDays | 단기 낙폭 기간 단위 |
| RsiPeriod | RSI 기간 단위 |
| VolumeLookbackDays | 이전 평균 거래량 기간 단위 |
| MovingAveragePeriods | MA 기간 목록의 단위: 일/주/월 |
| PivotLeftBars | 기존 고점의 왼쪽 비교 자료 단위 |
| PivotRightBars | 기존 고점의 오른쪽 확정 자료 단위 |
| VolumeZoneLookbackDays | 매물대 분석 자료 단위 |

값은 `{ "size": 1, "unit": 4 }` 같은 객체다. `parameterTimeframes`의 `size`는 분/시간에서 양의 크기, 일/주/월에서1이다. D 화면에 직접 연결한 기간 단위는 거래대금·중기·단기·RSI·거래량·매물대의6개이며, MA는 `dayTrading.support.movingAverageTimeframe`을 사용한다. D JSON에 나머지 기존 키를 보존할 수 있어도 D에 피벗 규칙이 추가되지는 않는다.

추가로 `configuration.crashStrategy.dayTrading.indicatorTimeframes`는 JSON 전용 지표별 사전이다. 키는 Rsi, Volume, MovingAverage, VolumeProfile, Liquidity, 값은 같은 TimeframeSpec 형식이다. 편집기는 이 사전을 보존한다. `advancedTimeframes:true`일 때 이 사전의 해당 override를 사용하고, 없으면 RSI·거래량·거래대금은 기본 분석봉, MA·매물대는 support의 기준을 사용한다.

통합 전략의 실행 정의를 만들 때 D의 `configuration.parameterTimeframes` 중 RsiPeriod→Rsi, VolumeLookbackDays→Volume, AverageTradingValueLookbackDays→Liquidity, VolumeZoneLookbackDays→VolumeProfile을 이 사전에 연결하고 `advancedTimeframes`를 켠다. 이4개가 명시되어 있으면 같은 지표의 JSON 전용 사전값보다 우선한다. 오프라인 일봉 실행에서는 이 override들을 비우는 앞선 정책이 우선한다.

## 7. JSON 형식과 불러오기 규칙

### 7.1 통합 형식

현재 전략 화면의 내보내기는 항상 바깥에 `schemaVersion:1`, `strategyId:"krx-oversold-rebound"`인 통합 파일을 만든다. D ON이어도 바깥 ID를 D로 바꾸지 않는다. D는 내부 `crashStrategy`에 버전2·ID `strategy-d-intraday-v1`로 들어간다.

```text
schemaVersion / strategyId / preset / exportedAt
└─ configuration
   ├─ useCrashStrategy: false 또는 true
   ├─ 기존 61개 설정
   ├─ parameterTimeframes: 기존 전략의 기간 단위
   └─ crashStrategy
      ├─ schemaVersion: 2
      ├─ strategyId: strategy-d-intraday-v1
      ├─ preset / exportedAt
      ├─ configuration: D의 기술적 수치·기간
      └─ dayTrading: D의 분석·급락·중첩·재진입·청산·운용·한도·자료 정책
```

`preset`은 전략 이름으로1~80자, 제어문자는 허용하지 않는다. `exportedAt`은 내보낸 시각의 메타데이터이며 거래 판단 시각이나 백테스트 시작일이 아니다. 실제 편집·내보내기 과정에서 이름·내보낸 시각은 갱신될 수 있다.

루트의 schemaVersion, strategyId, configuration은 필수다. 이전 버전의 파일에서 추가 필드를 생략하면 코드 기본값을 적용한다. `configuration` 객체 없이 숫자들만 나열한 파일은 받지 않는다. 일부만 적은 파일은 ‘기존 전략에 나머지 값 유지한 채 덮어쓰기’가 아니라 **생략값이 기본값인 새 전략**으로 들어온다. 논의용 JSON은 아래 전체 예제 또는 본인의 전체 내보내기 파일을 바탕으로 수정하는 편이 정확하다.

기존 단독 D 형식(schemaVersion2/strategy-d-intraday-v1/configuration/dayTrading)도 받으며, 불러올 때 통합 전략으로 감싸고 사용 체크를 ON으로 만든다. 다른 ID/버전은 기존 엔진으로 대체하지 않고 오류 처리한다.

### 7.2 값의 표현

- 객체 속성은 내보내기 형식인 camelCase를 권장한다. 항목명 대소문자는 허용하지만 오타는 허용하지 않는다.
- boolean은 소문자 `true`/`false`, 숫자는 따옴표 없이 입력한다. 정수 기간에 `14.5`를 넣거나 숫자를 `"30"`으로 넣으면 오류다.
- MA·분할비율 목록은 문자열이다: `"120,240,480,999"`, `"40,30,30"`.
- 현재 내보내기는 enum을 숫자로 쓴다. 현재 개발 소스의 importer는 숫자와 정확한 영문 enum 이름을 모두 받는다. 한글 화면 라벨은 enum 값이 아니다.
- 시간은 `"15:00:00"`, 시간대는 `"Korea Standard Time"` 같은 문자열이다.
- JSON에는 주석, 후행 쉼표, 같은 객체의 중복 키를 넣지 않는다. 대소문자만 다른 중복도 오류다.
- 알 수 없는 항목명을 무시하지 않는다. 오류 메시지의 JSON 경로를 확인해 고친 뒤 다시 불러온다. 설명 문장은 파일 밖에 둔다.

### 7.3 enum 숫자표

- `TimeframeUnit`: `0` = `Trade`, `1` = `Second`, `2` = `Minute`, `3` = `Hour`, `4` = `TradingDay`, `5` = `Week`, `6` = `Month`
- `WaitUnit`: `0` = `Second`, `1` = `Minute`, `2` = `Bar`, `3` = `TradingDay`
- `SignalEvaluationMode`: `0` = `OnTick`, `1` = `OnActiveBarUpdate`, `2` = `OnBarClosed`
- `RuleCombination`: `0` = `Any`, `1` = `All`
- `VolumeProfileSource`: `0` = `Approximate`, `1` = `TradeBased`
- `ReentryMode`: `0` = `NewLowerZoneOnly`, `1` = `SameZoneWithFreshSignal`, `2` = `NewZoneAnyDirection`, `3` = `Disabled`
- `ExitMode`: `0` = `FullTakeProfit`, `1` = `PartialTakeProfit`, `2` = `TrailingOnly`
- `TrailingPeakBasis`: `0` = `FromEntry`, `1` = `ResetAtTakeProfit1`
- `IndicatorKind`: `0` = `Rsi`, `1` = `Volume`, `2` = `MovingAverage`, `3` = `VolumeProfile`, `4` = `Liquidity`
- `DailyTouchPolicy`: `0` = `ConservativeHighLow`, `1` = `CloseOnly`
- `TrailingActivation`: `0` = `AfterEntry`, `1` = `AfterTakeProfit1`

`TimeframeUnit`의 Trade·Second는 원본 이벤트 엔진을 위한 값이다. 일반 전략 설정의 기간 콤보·parameterTimeframes는 Minute/Hour/TradingDay/Week/Month를 사용하며, MA는 TradingDay/Week/Month를 사용한다. 단독 D의 호환 JSON에 원본 체결·초 기준을 표현할 수 있어도 OHLCV 연구에서는 사용할 수 없다. `WaitUnit`은 별도 enum이므로 TimeframeUnit의 숫자와 혼동하면 안 된다. 예: 기간 단위0은 Second, 봉 단위0은 Trade다.

### 7.4 주요 조합 검증

- MA 기간은1~10000의 쉼표 구분 정수다.
- 분할 횟수와 비율 목록 길이가 같고 비율은 모두 양수·합계100이어야 한다.
- 예정 투자금 ≤ 초기 현금이어야 한다.
- 두 익절을 모두 쓰면 2차 목표 > 1차 목표, 활성 익절 비율 합계 ≤100이어야 한다.
- 기존 지지 유형을 하나 이상 사용해야 한다.
- D는 MA·매물대·반등 확인을 필수로 요구하고, 급락 종류를 하나 이상 사용해야 한다. 활성 급락 묶음 안에도 검사 규칙이 하나 이상 있어야 한다.
- D 후보 유효기간은 양수다. 횟수·자료 한도와 자금·위험 한도도 양수여야 한다.
- 주문당 금액 ≤ 전체 노출 한도, 종목 위험예산 ≤ 하루 손실 한도다.
- D의 신규 진입 종료 ≤ 청산 시작 시각이며 실제 실행에서 확인된 세션 범위도 확인한다.
- 추적 중심은 진입 직후 추적이 필요하다. 1차 익절 뒤 추적·본전 보호는 실제1차 부분익절이 가능한 조합이어야 한다. 보호 손절을 하나 이상 켜야 한다.
- D 사용 OFF여도 함께 저장한 D 설정은 유효해야 한다. 비어 있는 그룹, 잘못된 정책, 재중첩 전략은 거부한다.

### 7.5 불러오기 절차와 값의 보존

1. 전략 설정에서 ‘불러오기’를 누르고 UTF-8 `.json` 파일을 선택한다.
2. 앱이 전체 정의를 검증하고 등록 전략으로 저장한다. 이름이 이미 있으면 `이름 2`, `이름 3`처럼 새 이름을 붙인다. 기존 동명 전략을 덮어쓰지 않는다.
3. 선택된 전략의 입력창·사용 체크·봉 단위를 확인한다. OFF인 D의 저장값도 유지한다.
4. 필요하면 ‘내보내기’로 다시 저장해서 원본 JSON과 비교한다. 이름·내보낸 시각, 빠졌던 기본값·기본 단위 보충, 공유 자금·비용 정규화는 달라질 수 있다. 의미 있는 숫자·사용 여부·단위의 임의 변경은 없어야 한다.

오류나 파일 선택 취소는 등록 목록·기존 저장값을 바꾸지 않는다. 내보내기는 편집 중 현재값을 포함하므로 ‘저장’ 버튼으로 현재 등록 전략을 덮어쓰는 동작과 구별된다. 내보낸 파일에는 종목 목록·분석 시작/종료일·증권사 키·계좌·시세 원본이 포함되지 않는다.

## 9. ChatGPT와 논의할 때 전달할 요청문

다음 요청과 이 문서, 가능하면 본인이 내보낸 전체 JSON을 함께 전달하면 된다.

> 첨부 문서는 현재 프로그램에 구현된 전략과 JSON 스키마다. 먼저 급락 판단 전략 사용 ON/OFF 중 어떤 엔진을 논의하는지 확인해 줘. 문서에 없는 조건이 이미 구현되어 있다고 가정하지 말고, 현재 규칙의 논리적 장단점·충돌·자료 요구사항·과최적화 가능성을 분석해 줘. 수정 제안을 ‘기존 설정값으로 조절 가능’과 ‘코드 변경 필요’로 구분해 줘. 확정봉 연구와 원본 체결 실행의 차이를 고려하고 근사 매물대를 실제 체결 매물대로 해석하지 말아 줘. JSON을 제안한다면 완전한 통합 JSON으로 반환하고 모든 기존 키를 보존해 줘. 자금·비용은 바깥 설정이 원본이며 D 내부 기술적 설정과 바깥 기술적 설정을 혼동하지 말아 줘. 수익률을 보장하거나 검증하지 않은 백테스트 결과를 만들어 내지 말아 줘.

특히 논의할 만한 항목은 기본 기존 전략의 반등 확인 OFF, D의 기간·장중 OR 결합, MA·매물대 거리와 구간 폭, 새 반등 후보 만료, 추가매수와 위험예산, 손절/익절 동시 감지 순서, 분할 익절 정수 수량, 일봉과 당일 운용의 불일치다. 무엇을 바꾸느냐에 따라 단순 숫자 조절 또는 엔진 수정이 필요하다.

## 10. 이번 불러오기 점검 결과와 적용 범위

기존61개 설정과 D의 공통 수치·정책·봉 단위·JSON 전용 사전을 기본값·변경값으로 비교하고, D ON/OFF를 격리된 파일·DB로 검사했다. 실제 StrategyEditor의 불러오기→편집값→내보내기→복구→편집기 재생성 경로를 비교했다. JSON 객체의 값으로 비교했으며 소수값의 `1.10`과 `1.1`처럼 의미가 같은 표기 차이는 오류로 보지 않는다.

발견·수정한 문제는 가져온 지표 봉 크기가 편집기 적용 과정에서1로 초기화되는 경우다. 예를 들어 D의3시간 RSI가1시간으로 바뀔 수 있었다. 현재는 같은 단위를 유지할 때 가져온 크기를 보존하며, 기존 전략의 단위 바인딩에도 같은 보호를 적용했다. 또한 이전에는 알 수 없는 항목명이 조용히 무시될 수 있었으므로 항목명·내부 중복·잘못된 기간 키를 오류로 처리하도록 보강했다. 사용 OFF인 잘못된 D가 저장 후 열리지 않는 문제를 막기 위해 대기 설정도 저장 전에 검증한다.

관련 검사303개, Release 빌드0경고·0오류, Core192개·Avalonia 전체629개·디자인18개가 통과했다. 실제 계좌·원본 사용자 저장소를 검증한 수치가 아니며 모든 시장 시나리오의 전략 성과를 검증한 결과도 아니다.

이 설명서는 현재 개발 소스 기준이다. 수정된 importer는 v0.1.17 배포 대상에 포함된다. 로컬 개발 앱은 기존 앱을 정상 종료한 뒤 Rider의 `Mac · .app 빌드 후 실행`으로 갱신할 수 있다. 예제의 숫자 enum 형식은 이전 설치본에서도 쓰던 형식이며 새로 보강한 오류 처리·영문 enum 지원·봉 크기 보존은 v0.1.17에서 적용된다.
