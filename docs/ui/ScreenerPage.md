종목 조회는 최대 4개 묶음으로 병렬 처리한다. 종목별 일봉·보안상태·현재가는 서로 독립적으로 조회하고, 같은 종목의 현재가 공급자 대기시간이 다른 종목까지 막지 않는다. 10분 이내에 이미 받은 일봉은 다시 내려받지 않고, 지정봉은 종목·봉·기간·브로커별로 2분 동안 최대 128개 범위만 메모리에 보관한다. 진행 중에는 메모리 snapshot만 갱신하며 SQLite 전체 결과는 8종목마다 저장한다. 하단 상태에는 `전체 N개 중 K번째`, 총 경과시간, 종목당 평균시간과 함께 `자료조회`와 `전략계산` 평균을 따로 표시한다. 2026-10-14 공개 읽기 전용 상위 목록 검사에서는 KOSPI/KOSDAQ 각 10개, 합계 20종목의 최근 1주를 두 번 측정해 9.52초와 9.55초가 걸렸다. 네트워크와 제공처 상태에 따라 달라질 수 있다.

온라인 키움 국내 연결에서 `분봉` 또는 `시간봉`을 고르고 숫자 콤보에서 분봉 1~59, 시간봉 1~12를 선택한다. 단위를 바꾸면 이전 숫자는 새 범위 안으로 자동 보정한다. 키움이 직접 지원하는 간격은 해당 값을 `ka10080.tic_scope`로 요청하며, 특히 1시간봉은 공식 60분봉을 바로 읽는다. 그 밖의 분/시간은 1분봉을 장 시작 경계 기준으로 집계한다. 키움 분봉 응답에는 정확한 체결대금이 없으므로 거래대금은 `(O+H+L+C)/4 × 거래량` 근사값임을 결과에 표시한다. 기술 조건은 계속 평가하지만, 확인되지 않은 과거 상품 분류·거래정지·관리·위험 항목은 `자료부족`으로 남고 실제 주문 승인에는 사용할 수 없다. 진행 요약의 `조회 실패/봉 없음`은 봉을 전혀 만들지 못한 종목만 센다.

20일 1시간봉 40종목처럼 느린 경우의 주 병목은 키움 REST 요청이다. 브로커 요청은 안전을 위해 직렬화하고 최소 650ms 간격을 지키므로 한 종목당 최소 한 번의 네트워크 대기가 누적된다. 전략 계산은 이미 백그라운드에서 실행되고 화면에는 실제 계산시간을 별도로 표시한다. 이 경로를 Rust/C++로 옮겨도 API 대기시간은 줄지 않으며 네이티브 DLL 배포와 장애 지점만 늘어난다. 따라서 현재는 60분봉 직접 조회, 범위 캐시, 불필요한 종목 상세 조회 제거가 적합한 최적화다.

현재 상장 목록이므로 과거 전체시장이나 생존편향을 제거한 목록이 아니다. 당시 분류/실제 거래대금/위험/검증된 거래일 자료가 없으면 진입 조건을 임의 추정하지 않는다. 누락·실패와 해외 제외·중복 제거 개수를 표시한다. 그룹 미선택은 전체시장으로 대체하지 않는다. 구형 전략·Pipeline 설정이나 모의 순위 공급자로 우회 실행하지 않는다.

상세 창은 스크리닝 실행 snapshot의 지정봉을 첫 주기로 선택한다. 일봉은 보조 비교 주기로 제공한다. 연결 계좌의 분봉이 있으면 실행 당시 N분/N시간봉을 구성한다. 이전 버전에서 저장한 틱 snapshot은 읽기 호환을 위해 표시할 수 있지만 새 지정봉 UI에서는 틱을 선택하지 않는다. 자료가 없을 때 일봉을 잘게 나눠 지정봉으로 만들지 않는다. 매수·매도는 종목/차트의 백테스트 표식과 같은 `#번호 ▲ 매수`·`#번호 ▼ 매도` 방식과 하단 한국시간·가격·수량·사유 표에 함께 표시한다. 시간봉도 장중 주기로 처리해 X축 시각과 체결이 해당 시간봉에 맞춰진다.

상세 차트의 첫 화면은 snapshot 시작일 00:00부터 종료일 다음날 00:00 직전까지의 봉만 사용해 시작일~종료일 전체를 보여주는 잠금 상태다. 저장된 백테스트·실제·모의 체결도 이 경계 안의 표식만 함께 표시하므로 다른 날짜의 체결이 첫/마지막 봉에 붙지 않는다. 이 상태에서는 휠·좌클릭·드래그·표식 선택이 동작하지 않는다. 원하는 봉에서 우클릭하면 그 봉을 가운데에 두고 최대 500봉 범위로 확대되며 이후 휠 확대·축소, 좌우 드래그, 매매 표식 선택을 사용할 수 있다. 휠 축소는 처음 우클릭으로 열린 범위를 넘지 않는다. 다시 우클릭하면 전체 기간 화면으로 복귀하고 입력이 잠긴다. 스크리닝 본문 목록과 `스크리닝 결과 → 종목별 조건·체결`은 같은 창과 동작을 사용한다.

## 실시간 스크리닝

### 기본 결과는 전략 일치 종목 (2026-11-06)

선택한 시장/관심그룹의 대상 전체를 내부에서 계속 평가하되, 기본 표에는 **현재 전략의 활성 조건을 모두 통과한 종목만** 표시한다. 준비 봉의 마지막 확정봉에 대한 공통 전략 평가를 사용하며 OFF 조건과 진단용 수치는 필터에서 제외한다. 시세가 끊기거나 오래된 종목, 자료 미확인/미평가 또는 조건 미충족인 종목은 일치로 표시하지 않는다. 시세만 달라지고 지정 봉이 아직 마감되지 않았다면 확정봉 조건은 그대로다.

`전체 대상·미충족 사유 보기`를 체크하면 내부 감시 중인 모든 대상과 준비 실패 종목을 확인한다. 조건 충족 수·미충족 사유·자료 상태는 기본 일치 표와 같은 평가 snapshot이다. 체크를 해제하면 다시 일치 종목만 표시한다. 하단에는 검사 대상/분석/전략 일치/자료 미확인 수를 따로 보여준다. 조건을 벗어난 종목은 결과에서 사라지지만 내부 감시에서는 제거하지 않는다. 전략 일치와 실제 주문·체결은 별개이며 자동매매의 계좌/위험 검사는 계속 적용한다.

온라인 준비는 지정 봉을 정확히 구성할 수 있는 키움 native 분 간격을 우선 사용한다. 전략의 활성 지표에 필요한 과거 봉 수를 확보하면 다음 페이지를 요청하지 않는다. MA999를 켠 경우 필요한 과거 자료를 줄이지 않는다. 자료 조회와 현재 상태 확인은 동시에 진행하며 무거운 전략 준비는 UI 스레드 밖에서 수행한다. API 제한과 자료 길이에 따라 준비 시간이 달라진다.

실시간 종목 더블클릭 시 저장 체결 DB를 읽지 못하면 해당 체결을 표시하지 않고 창 안에 읽기 오류를 안내한다. 조회 가능한 봉과 모형 백테스트는 계속 표시하며 실제 체결로 꾸미지 않는다. 차트/이전·다음 자료 처리 실패도 프로그램 종료 대신 안내로 처리한다. 사용자 DB는 삭제하거나 초기화하지 않는다.

같은 `스크리닝` 탭의 `일반 스크리닝 / 실시간 스크리닝` 모드로 전환한다. 새 메인 탭이나 별도 전략 엔진을 만들지 않는다. 실시간 모드는 저장된 과매도·낙주 전략 snapshot, 분봉 또는 시간봉, 시장별 상위 10·25·50·100개를 사용한다. 온라인 키움 연결은 실제 체결·호가, 오프라인은 네이버 공개 현재가와 완성 분봉을 사용한다. 틱 지정봉과 미완성 일봉은 실시간 확정봉 판단에 사용하지 않는다.

결과 표는 현재가·등락률, 조건 접근도, 충족 조건 수, 미충족 조건, 전략 상태, 자료 상태, 주문 상태, 마지막 분석시각을 분리해 보여준다. 접근도는 각 조건의 현재값과 기준값 사이 거리를 0~100으로 정규화한 **조건 근접도**일 뿐, 수익 확률이나 주문 신호가 아니다. 최종 `매수 신호`는 기존 `OversoldLiveStrategy`가 동일한 설정과 시점별 자료로 실제 진입 조건을 모두 만족한 경우에만 발생한다. 집중 감시가 아닌 종목도 평가에서 제거하지 않는다.

`자동매매 시작`은 기본 해제다. 현재 새 화면은 안전하게 **가상 계좌 주문만** 연결하며 실제 증권사 주문을 전송하지 않는다. 시작 전 체크하면 시작 이후 신호부터, 실행 중 체크하면 체크 이후 새 신호부터 가상 주문이 가능하다. 이미 지난 신호는 소급 주문하지 않는다. 해제하면 신규 진입·추가매수만 즉시 막고, 기존 가상 포지션의 익절·손절 등 보호 관리는 계속한다. 기존 실계좌 다량 전략 창은 별도의 확인·한도·OrderGuard 경로로 유지된다.

실행 서비스는 View나 팝업이 아니라 `WorkspaceViewModel` 수명에 속한다. 탭을 옮겨도 계속 동작하고, 다시 돌아오면 같은 상태를 표시한다. 종목 준비는 최대 4개씩, 실시간 피드는 증권사 제한에 맞춰 20종목 단위 shard, 화면 갱신은 최대 500ms 간격으로 제한한다. 종목 하나의 오류는 해당 행만 오류로 두며 다른 종목은 계속 감시한다. 시세 연결 끊김·지연·긴급중지는 신규 주문을 차단하고 실행 상태를 중지로 바꾼다. 일반 중지는 신규 감시와 진입을 멈추되 보유 가상 포지션을 임의 청산하지 않는다.

자동검사는 가짜 피드로 조건 접근→신호→체크 시점 경계→가상 주문→체결 표식→보호 매도→중지와 연결 장애를 검증한다. 2026-11-05 장중 실제 공개·키움 시세 검증은 `docs/verification/Realtime-2026-11-05.md`에 별도 기록한다. 실계좌 주문은 실행하지 않는다.

증권사 준비 분봉에서 실제 관측한 과거 거래일을 `WithObservedWarmupSessions`로 전략의 거래일 목록에 전달한다. 기존 입력 거래시간은 유지하며, 과거 종목상태·위험을 현재 값으로 채우지 않는다. 상태·위험을 확인하지 못한 종목도 연구 감시는 계속할 수 있지만 가상 자동매매 대상에는 넣지 않는다.

오프라인에서는 공개 분봉을 14일 범위로 준비하고 분당 다시 읽는다. 현재가는 종목 최대 20개씩 묶어 장중에는 1초 간격으로 조회하고 장 마감에는 제공처 `pollingInterval`을 따른다. 공개 시세의 가격·변동·마지막 분석 결과를 표시하고 기존 `OversoldLiveStrategy`를 연구 전용으로 재사용한다. 자동매매 체크는 비활성화되어 실제·가상 주문을 만들지 않는다. 원본 체결 이벤트도 저장하지 않는다. 장 마감 시 마지막 공개가와 장 마감 상태를 보여주며 신규 신호를 보류한다. 날짜가 바뀌면 새 분봉과 시장 상태를 준비하도록 감시가 중지된다. 공개 데이터의 지연·누락·서버 변경 가능성을 화면에 표시한다.

### 실시간 행·차트·전략 전환 (2026-11-05)

`RealtimeScreeningDisplayRow`는 종목별 객체를 유지하면서 속성만 갱신한다. 500ms 화면 갱신 때 Collection을 초기화하거나 순위를 강제로 바꾸지 않으므로 선택과 더블클릭이 유지된다. 사용자가 열 머리글로 정렬할 수 있다.

실시간 표를 더블클릭하면 기존 `ScreeningChartDialog`가 현재 감시의 지정봉·전략 snapshot을 사용한다. 완성 봉, 확인된 실제/가상 체결과 공통 BacktestService가 계산한 과거 모형체결을 표시한다. 모형체결은 출처에서 구분하며 계좌 체결로 저장하지 않는다. 익절·손절·청산 이유는 공통 `TradeOutcome`을 사용한다.

실행 중 저장 전략을 바꾸면 표를 한 번 비우고 Background에서 지표·후보 상태를 다시 준비한다. 이전 버전의 대기 UI 응답을 무시하고 준비 중 추가로 완성된 봉은 새 상태에 따라잡는다. 준비 동안 시세 수신과 이전 가상 보유분의 보호 매도는 유지한다. 자동매매는 해제하며 새 전략으로 자동매매하려면 감시를 다시 시작해야 한다. 중지 가능한 상태의 중지 버튼은 옅은 빨강이다.

관심종목 소스를 고르면 상위 개수·목록 불러오기 컨트롤 대신 같은 행의 관심그룹 선택을 표시한다. 시장·분야 필터는 두 소스에 공통이다. 그룹은 가로 스크롤하며 컨트롤 높이를 키우지 않는다.

### 2026-10-05 갱신
선택한 확정봉을 과거부터 순차 평가하는 새 결과창으로 확장했다. 이전 문서의 '마지막 하루·빈포지션 평가' 설명은 더 이상 적용되지 않는다. 신규 데이터 기준/자료부족 처리/immutable snapshot/행 상세는 [ScreeningResults.md](ScreeningResults.md) 참고. 실시간 실행은 스크리닝 후보와 별개이며 검증된 틱·분 준비봉과 시점별 안전 자료를 다시 확인한다.

## 2026-11-06 변경

기본 실시간 표는 전략 일치 또는 전략에 저장된 최소 접근도 이상의 근접 후보를 표시한다. `전체 대상·미충족 사유 보기`는 그 외 대상/실패도 표시한다. 고정60점은 별도 집중 감시 임계값으로 사용하지 않으며 후보 최소 접근도는 전략별 설정이다. 실제 매수는 기존 공통 엔진의 전체 조건을 충족해야 한다.

실시간 시작 시 장외이면 새 팝업으로 안내하고 세션을 시작하지 않는다. 오프라인은 준비 전 공개 시세의 CLOSE 상태도 확인한다. 자동매매/데이터 구독을 시작하기 전 검사한다. 정규 연속매매 구간 외와 시세 지연/실패는 별개로 표시한다. 실시간 지정봉 감시는 국내만 지원하며 해외 시장 선택에는 일봉 연구 안내를 표시한다.

일반/실시간 감시 결과는 `테스트 기록`에 남긴다. 일반은 종료/실패/취소 상태와 처리한 결과, 실시간은 중지/종료 시 실행 한 번당 마지막 평가와 원본을 저장한다. 기존 포지션 보호 정책은 바꾸지 않는다.

## 일반 스크리닝 중 결과 열기 (2026-11-07)

작업 중에도 `스크리닝 결과`로 현재 집계와 완료된 종목을 보고, 완료된 후보 이름/더블클릭/`백테스트 보기`로 독립 차트를 열 수 있다. 시장·전략·봉·기간 변경과 중복 시작은 계속 잠근다. 동일4개 병렬 요청 안에서도 Task.WhenEach로 한 종목이 끝나는 즉시 반영한다. 결과 창은250ms로 새 snapshot을 읽되 종목 선택을 유지한다. 차트는 그 종목의 당시 원본·설정·공통 엔진을 사용하며 진행 중 검사/취소 토큰/종목·차트 탭을 변경하지 않는다. 다음/이전은 같은 실행에서 새로 완료된 종목까지 탐색한다. 저장소 오류는 자료부족으로 숨기지 않고 검사를 중단한다.

관련: CanReviewScreeningResults, ScreenOversold, ScreeningNavigation, ScreeningResultDialog, MainWindow, ProgressiveScreeningTests.

## 2026-11-07 데이터 기준 정책

일반/실시간 모드 모두 오프라인은 일봉으로 고정하고 지정봉 컨트롤을 숨긴다. 온라인은 지정봉(분1~59,시간1~12) 또는 일봉이다. BarUnit.Day를 추가했고 일봉은 검증된 장 시작~마감 구간 전체를 의미한다. 일봉 실시간 분석은 미완성 당일봉으로 매수 신호를 확정하지 않는다. 장중 화면 현재가 갱신과 봉 마감 전략 판단은 별개다. 새 데이터를 기다리는 상태에서 주문을 만들어 보이지 않도록 한다. 일반 스크리닝의 진행 중 결과 열람 기능은 유지한다.
