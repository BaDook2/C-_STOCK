# 국내 과매도·낙주 반등 일봉·분봉·시간봉 백테스트

## 목적과 동작
국내 종목의 급락, 과매도 필터, 지지 후보 cluster를 과거 시점 순서대로 검사한다. 종목 검색·차트, 수동 모의매매, 정기매수, 원본 틱, 선택 계좌 수동 주문을 유지한다. 현재 선택·등록·스크리닝·백테스트에는 이 전략만 제공한다. 실계좌 다량 실행은 같은 설정을 사용하되 검증된 실시간 체결과 오늘의 시점별 자료가 있는 선택 키움 국내 계좌에서만 별도 시작 확인 후 허용한다.

1. 종목·차트에서 국내 종목 이름을 검색한다. 첫 결과가 자동으로 열리며 Enter도 동작한다.
2. 전략 설정 탭 → 국내 과매도·낙주 반등을 펼친다. 백테스트 전용 / 공통 전략 조건 / 온라인 투자 전용으로 구분된 영역에서 설정한다. 대상/필터, 지지·반등, 예산, 청산, 기간, 비용은 하위 그룹으로 유지한다. 온라인 영역에는 현재 미지원 상태를 안내한다.
3. 당시 상태·실제 거래대금·위험·시장 거래일 자료를 적용한다. 부족하면 날짜별 판단에 이유가 남는다. 자세한 JSON 형식은 `docs/api/OversoldHistoricalFacts.md` 참고.
4. 종목·차트 오른쪽 **전략 백테스트** 탭에서 전략과 날짜를 선택한다. 오프라인은 일봉, 온라인에서 분봉 이력을 지원하는 국내 계좌를 연결하면 **지정 봉 → 분봉/시간봉 → 숫자**를 선택할 수 있다. 숫자 콤보는 분봉 1~59, 시간봉 1~12다.
5. **백테스트**를 누른다. 지정 봉은 완성된 N분/N시간봉 종가까지 판단하고 다음 완성봉 시가에 체결한다.
6. 같은 위치의 평가자산/승률/MDD/CAGR/기대손익/PF와 **상세 결과 · 판단 기록**을 확인한다.
7. 테스트 기록에서 이전 실행을 선택 → **과매도·낙주 상세 기록 열기**. 재실행 후에도 조회 가능하다.

## UI 대응
| UI | 동작 | 코드 |
|---|---|---|
| 설정·시점 자료 적용 및 저장 | 범위/교차검증, 기존 SQLite state에 저장 | `SaveOversold` |
| 시점 자료 JSON 읽기 | 선택 파일을 검사하고 편집란에 반영; 저장은 별도 | `낙주자료불러오기` |
| [?] | 중앙 Metadata의 Tooltip / 공통 상세 팝업 | `ParameterField`, `ParameterHelpDialog` |
| 백테스트 | 선택 전략 snapshot → background Core engine → 결과/근거/기록 저장 | `RunOversold` |
| 지정 봉 · 분봉/시간봉 | 단위 콤보와 범위별 숫자 콤보 → 공식 과거 분봉 범위 조회 → 완성 N분/N시간봉 → 공통 백테스트 서비스 | `TimeBarSelection`, `ScreeningBars`, `OversoldBacktestService` |
| 상세 결과 · 판단 기록 | 성과, 거래별 근거·체결, 날짜별 판단, 상태 전이, 설정 snapshot | `OversoldResultDialog` |
| 테스트 기록 상세 | 선택한 과거 결과 ID로 읽기 | `낙주기록상세` |

설명은 `OversoldConfig`의 `ParameterAttribute`에 있고 Label/Tooltip/Popup/검증이 공통 `ParameterCatalog`를 사용한다. View에 전략 계산을 넣지 않는다. 새 전략은 기존 Standard/Advanced 틱/파이프라인 엔진의 파라미터를 바꾸지 않는 별도 일봉 설정이다.

## 표시와 경계
- 숫자는 1,000 형식. 전략 소수 입력은 focus/blur 모두 2자리. 기존 0.015는 0.02로 표시하되 무편집 저장 시 원값을 보존하고 Tooltip에 정확값을 알린다. 실제 편집한 항목만 두 자리값으로 저장한다. 종목코드·날짜는 숫자 금액 포맷 대상이 아니다.
- 결과의 미산출 통계는 0으로 오인되지 않도록 `미산출`, 이익만 있을 때 PF는 `∞`.
- 거래 일시는 한국시간. 일봉·분봉·시간봉 모두 신호의 마감 시각과 다음 봉 시가 체결 시각을 별도로 표시한다.
- 분·시간봉 백테스트는 온라인 연결에서만 보인다. 연결 증권사가 지정 간격을 직접 제공하면 그 범위를 사용하고, 직접 지원하지 않는 간격은 공식 1분봉을 KRX 09:00~15:30 세션 경계로 집계한다. 틱을 분봉으로 만들거나 일봉을 잘게 나누지 않는다.
- 키움 분봉 응답에는 정확한 분당 체결대금 필드가 없어 `OHLC 평균 × 거래량` 추정값을 사용하며 결과 안내에 남긴다. 과거 종목 상태·위험 자료의 엄격한 진입 제한은 일봉과 동일하다.
- 같은 분·시간봉 안에서 고가와 저가 중 무엇이 먼저였는지는 알 수 없으므로 Stop을 익절보다 먼저 처리한다. 현재 봉 신호를 현재 봉 가격으로 체결하지 않는다.
- 실행은 백그라운드 Task이며 작업 취소·긴급중지 토큰을 따른다. 1분봉 20거래일 7,800개 기본 지표 부하 검사는 1,646ms, 결과 보유 메모리 증가 24.4MB였다. 테스트 장비 수치이며 실제 API 응답 시간은 포함하지 않는다.
- 기본 미청산은 마지막 종가로 강제청산하지 않고 평가자산에만 반영한다.
- 지지선은 MA/확정 pivot/일봉 근사 거래량 구간이며 실제 틱 volume profile이라고 표시하지 않는다.
- UI 검사는 숨긴 WPF 창 1,540×1,040 및 1,160×760 렌더와 command binding을 사용한다. 실제 물리 마우스 체감·다른 모니터 DPI 검증과는 다르다.
- 별도 시장 세션 배열이 비어 있어도 존재하는 완성 일봉 날짜에서만 당일 세션을 파생해 날짜별 판단을 남긴다. 과거 종목상태·위험·실제 거래대금이 없으면 기본 전략의 신규 진입은 계속 보류된다.

## 엔진 확인용 전략 3개

앱 시작 시 같은 이름이 없을 때 아래 일반 전략 프리셋을 저장한다.

| 전략 | 기대 청산 | 용도 |
|---|---|---|
| 백테스트 검증 1 · 1일 보유 | MaxHoldingDays | 다음 시가 진입과 보유기간 청산 확인 |
| 백테스트 검증 2 · 초단기 익절 | TP1 | 고가 접촉 익절과 다음 시가 청산 확인 |
| 백테스트 검증 3 · 지지이탈 | SupportBreak | 진입 cluster 하단 기준 손절 확인 |

이 세 프리셋은 `가격자료 검증 모드`가 켜져 있다. 공개 일봉만으로 엔진이 판단·상태전이·체결·성과를 생성하는지 확인하기 위한 설정이며 실제 투자 성과나 실시간 주문 승인으로 해석하지 않는다. 기본 투자 전략은 이 가정을 사용하지 않는다.

## 프리셋과 스크리닝
`OnlyOversoldWorkspace`에서 공개 실행 경로를 통일한다. 프리셋은 기존 SQLite state의 `oversold-presets-v1` / `oversold-preset:<이름>`에 저장한다. 예전 `chart-presets` / `strategy-configuration-*` 값과 테스트 기록은 삭제하지 않지만 실행 설정으로 복원하지 않는다. 구형 자동 재생·틱 전략·Pipeline 명령도 비활성화한다.

스크리닝은 선택한 관심그룹을 시장+종목으로 중복 제거하고 지역·분야 필터를 적용한다. 국내 종목의 확정 일봉 또는 연결 계좌 분·시간 집계봉을 기준으로 동일 Oversold 엔진을 실행한다. 해외는 지원 범위 밖으로 제외하고, 당시 상태/거래대금/위험/검증 거래일 자료가 없으면 실제 주문을 허가하지 않는다. 지정 봉 연구에서는 기술 조건을 계속 계산하되 누락 사실은 자료부족으로 유지한다. 과거 전체 시장을 재현하는 스크리너는 아니다.
