# 다량 종목 과거 모의·실시간 모의·실계좌 설정

다량 실행 창의 **등록 전략** 목록은 전략 설정 탭의 저장 전략 목록과 같은 저장소를 사용한다. 전략 설정에서 추가·JSON 불러오기·이름 변경한 전략은 다량 실행 창을 열거나 새로 고칠 때 그대로 나타나며, 각 종목은 선택한 저장 설정을 독립적으로 사용한다. 목록에서 삭제되었거나 이름이 바뀐 옛 선택값은 현재 첫 번째 저장 전략으로 안전하게 되돌린다.

다량 실행 창은 **모의**가 기본 체크 상태이며 `실시간`을 별도로 선택한다. `모의 ON + 실시간 OFF`는 종목별 과거 백테스트, `모의 ON + 실시간 ON`은 실제 키움 체결·호가를 사용하는 가상 체결, `모의 OFF`는 검증된 선택 키움 국내 실계좌 자동매매다. 실제 모드는 항상 실시간이므로 실시간 선택은 잠긴다. 이전 실행 목록을 자동 재개하지 않으며 기존 DB·실행 기록을 삭제하지 않는다.

오프라인의 **다량 전략 모의 백테스트** 팝업에서는 여러 관심그룹의 종목을 체크하거나 최신 스크리닝 후보를 가져온다. 같은 시장·종목은 한 번만 실행하며 중복 행의 체크 상태가 함께 바뀐다. 선택 목록과 그룹은 기존 SQLite의 `multi-trade-draft`에 저장된다. 선택한 국내 종목마다 현재 낙주 전략을 지정 기간의 확정 일봉에 적용하고, 종목별 결과와 `mock-batch:*` 기록을 저장한다. 전체 중지 전까지 목록 수정을 잠근다. 팝업을 닫아도 결과는 남으며 실제 주문은 발생하지 않는다.

온라인에서 **모의와 실시간을 함께 체크**하면 `RealtimePaperStrategyBatch`가 선택 종목별 가상 현금·보유·미체결을 독립 관리한다. 실제 키움 WebSocket 체결·호가와 검증된 틱/분봉 준비 자료를 기존 `OversoldLiveStrategy`에 공급하지만 `RemoteTradingSession`이나 증권사 주문 API는 호출하지 않는다. 신호를 만든 이벤트에서는 체결하지 않고 다음 실제 이벤트부터 `PaperBroker`의 가상 체결 규칙을 적용한다. 중지는 새 가상 주문을 막고 가상 미체결만 취소하며 보유분을 자동 청산하지 않는다.

실시간 모의 체결은 source가 `실시간 모의매매`인 공통 `TradeMarker`로 저장된다. 선택 종목 차트는 다중 전략이 소유한 WebSocket을 공유해 중복 구독을 만들지 않으며, 같은 체결시각·가격을 틱봉·분봉·일봉·주봉에 표시한다. 표식을 클릭하거나 표식이 있는 봉을 클릭하면 기존 거래 상세 UI가 같은 기록을 보여준다.

온라인의 **다량 전략 매수 설정** 팝업은 현재 선택해 연결한 계좌와 목록을 확인한다. 모의를 해제한 뒤 틱/분 기준, 오늘의 시장 세션·일반주식/정지/관리/위험 자료, 실제 거래대금이 있는 검증된 원본 준비 봉을 요구한다. 자료 부족·해외 종목·타 증권사 계좌·시간봉에서는 주문 없이 이유를 보여준다. 시작 확인창에는 선택 계좌·종목·예산·1회 한도·데이터 기준이 표시된다. 여러 계좌로 주문을 분산하지 않는다.

실제 주문 경로는 확인된 완성봉 이후의 체결에서만 신호를 평가한다. 기존 `LiveStrategyBatch → RemoteTradingSession → OrderGuard`가 계좌 점유, 보유·미체결 충돌, 현금/노출/손실 한도, 시세 신선도, 내구성 있는 주문 의도, 체결번호 대사를 검사한다. 실제 체결번호 없이는 포지션을 늘리지 않는다. 주문 응답 불명은 자동 재전송하지 않는다.

온라인 투자에서 **실제 계좌 주문 → 전략 다중매매**를 연다. 현재 선택·연결한 단일 계좌만 사용한다. 다른 증권사의 저장된 키로 주문을 분산하지 않는다.

종목·차트의 **가상 계좌 주문 → 실시간 전략 모의매매**로 열면 팝업은 `모의 + 실시간`으로 잠긴다. 이 경로에서는 계좌 연결 여부와 관계없이 증권사 주문 API를 호출하지 않는다. **실제 계좌 주문 → 전략 다중매매**로 열면 실제 모드로 잠기고 현재 연결 계좌를 명시한다. 일반 진입 경로는 기존처럼 실행 전 모의/실시간 선택을 허용한다.

실행은 팝업을 닫아도 계속된다. 메인 주문 탭에서 상태와 전체 중지를 사용할 수 있다. 계좌 교체·오프라인 전환·앱 종료는 먼저 실행 중지와 피드 종료를 기다린다. 목록·전략 선택·예산만 복원하며 앱 시작 시 주문을 자동 재개하지 않는다.

실행 버튼은 지원되지 않는 연결에서도 이유를 확인할 수 있도록 클릭 가능하게 둔다. 클릭 뒤 실제 시작 직전에 키움 국내 실시간 연결, 모의/실시간 선택, 시장 세션, 데이터 기준, 검증 원본 준비 봉을 다시 검사한다. 하나라도 충족하지 않으면 주문이나 가상 실행을 시작하지 않고 별도 안내 팝업에 정확한 조건을 표시한다.

전략 계산식 자체는 `N개 봉`을 입력으로 받으므로 틱봉과 분봉 모두 같은 낙주 로직을 사용한다. 다만 `100틱봉`과 `5분봉`은 한 봉이 닫히는 기준과 담는 시장 시간이 달라 같은 기간 값이라도 신호 시각과 준비 봉 수가 달라진다. 실시간 실행기는 미래 자료를 섞지 않고 **닫힌 봉**을 확정해야 하므로 현재는 실제 체결로 종료를 확정할 수 있는 틱봉과 분봉만 연결한다. 장중 일봉은 장 마감 전 미완성이고 시간봉은 실시간 준비자료·종료 경계 검증이 아직 연결되지 않아 실시간 주문에 사용하지 않는다. 선택 종목마다 해당 틱/분 기준의 검증된 원본 체결, 오늘 시장 세션과 시점별 거래 가능 상태가 없으면 가짜 봉으로 대체하지 않고 시작을 막는다.

기존 수동 보유/미체결이 있는 종목은 시작하지 않는다. 전략이 실제 체결번호로 확인한 수량만 매도할 수 있다. 실행 중 외부 주문 또는 보유량 불일치가 감지되면 해당 종목 주문을 막는다. 중지는 보유분을 자동 청산하지 않는다. 실제 시장가 체결은 확인 가격과 달라질 수 있다.

주문 접수, 부분 체결, 취소 접수, 취소 확인을 구분한다. 응답 불명은 재전송하지 않으며 증권사에서 확인해야 한다. 화면 손익은 실제 체결가격의 수수료 전 손익이고, 손실 차단 계산은 등록된 수수료·세금 가정을 차감한다. 실제 증권사 청구 비용을 조회한 값으로 표시하지 않는다.

다중매매 실행 중 수동 매수·매도와 외부 확인 해제를 막는다. 실시간 feed를 실행 서비스가 사용하므로 별도의 차트용 구독은 열지 않는다. 수집된 원본은 SQLite에 보존하며 원본 틱 탭에서 조회할 수 있다. 실계좌·실키로 수행한 검증은 없으며 FakeBroker/FakeFeed/공식 스키마 HTTP fixture로 검사했다.

저장: 기존 workspace-v2.db state의 multi-trade-draft, live-batch:<계좌 해시>, live-batch-daily:<계좌 해시>:날짜. 주문 write-ahead journal은 기존 계좌별 JSON을 재사용한다. 비밀키를 추가 저장하지 않는다.

## 2026-10-11 화면 구성

다량 전략 창은 공통 밝은 Canvas 위에 검색·관심그룹·모의/실계좌 예산 설정 카드, 선택 종목과 실행 상태 표 카드, 실행·중지·삭제·저장 제어 카드로 나뉜다. 실행만 파란 주요 동작으로 표시하고, 선택 종목 중지·행 삭제·저장·외부 확인은 회색 보조 동작으로 구분한다. 전체 중지는 옅은 붉은색으로 위험 동작임을 나타낸다. 팝업을 닫아도 Application-level 다량 실행 상태와 선택 목록은 유지되는 기존 동작을 바꾸지 않는다.
