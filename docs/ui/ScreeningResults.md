# 스크리닝과 결과 (2026-10-21)

## 사용법

일봉은 기존 공개 과거 자료를 사용한다. 온라인에서 지정 봉을 선택하면 단위 콤보에서 분봉/시간봉, 숫자 콤보에서 분봉 1~59 또는 시간봉 1~12를 고른다. 단위를 바꾸면 숫자는 새 범위 안으로 자동 보정한다. 잘못된 이전 저장값은 분봉 범위로 정규화하고 마지막 설정은 기존 SQLite state로 복원한다.

스크리닝 시작 옆의 **스크리닝 결과**는 0건이거나 진행 중이어도 열 수 있다. 각 실행은 당시 설정·대상·기준 봉·관측 시각·원본 기간·조건별 값과 최종 후보를 저장한다. 이후 설정 수정은 과거 결과를 바꾸지 않는다. 현재 UI는 최신 실행을 열며 과거 snapshot은 DB에 보존한다.

기간 스크리닝은 화면에서 시작일과 종료일을 고른다. 시작일 이전 봉은 지표 준비에만 사용하고 종료일 이후 봉은 판단하지 않는다. 결과 행에는 조건이 맞은 날짜가 표시된다. 후보 표의 파란 종목 이름을 누르거나 결과창에서 행을 더블클릭하면 메인 종목·차트 탭을 변경하지 않고 독립 상세 창을 연다. 일봉 실행은 저장 당시 설정과 자료로 같은 기간의 **모형 백테스트**를 계산해 marker와 표를 표시한다. 지정 봉 스크리닝은 스크리닝 자체에서 가짜 체결을 만들지 않으며 저장된 실제·모의 체결만 함께 표시한다.

| 화면 | 내용 | 코드 |
|---|---|---|
| 단계별 집계 | 통과/실패/미평가/자료 부족 및 사용 안함 | OversoldScreeningRun.Funnel |
| 지지 유형 진단 | MA/Pivot/근사 구간을 독립 표시. 3개 모두를 요구하지 않음 | OversoldEntryDetector |
| 종목별 조건·체결 | 계산값·기준값·제외 이유 및 보관된 전략 신호·체결 | ScreeningResultDialog |
| 실행 당시 설정 | 변경되지 않는 설정 JSON | ConfigJson |
| 후보 표 | 코드/종목/가격/관측 시각/급락률/RSI/거래량 배수/지지 개수/상태 | ScreeningRow |
| 후보 이름 클릭·결과 행 더블클릭·백테스트 보기 | 같은 명령으로 별도 창의 일봉/실행 당시 분·시간봉과 판단 당시 매수·매도 시점. 이전 틱 snapshot은 읽기 호환 | OpenScreeningStock / ScreeningChartDialog |

사용 안함은 통과 수에 포함하고 별도 열은 그중 비활성 조건 수다. 통과+실패+미평가+자료부족=전체 대상 수다. 지지 유형 3개는 같은 진입집합의 독립 가지이며 누적 필터가 아니다.

**자료부족**은 해당 단계에 필요한 과거 봉, 과거 종목 상태, 실제 거래대금 또는 지표 준비값을 확보하지 못했다는 뜻이다. **미평가**는 아직 해당 종목을 처리하기 전이거나 앞 단계에서 이미 탈락했거나 자료가 부족해 이후 조건을 실행하지 않았다는 뜻이다. 온라인 지정 분·시간봉 연구에서는 상품 분류·정지·관리·위험 이력이 없어도 가격 기반 기술 조건은 독립적으로 계속 평가한다. 누락 조건은 자료부족으로 남고 주문 승인에는 쓰지 않는다. 결과창 상단에서도 이 설명과 ToolTip을 표시한다.

## 봉과 원본 자료

- 집계 입력은 명시된 시장 세션(시가·종가 시각)을 사용한다. 임의 평일을 거래일로 추정하지 않는다. 표시 시각은 한국시간이다.
- 과거 틱 지정봉 snapshot은 timestamp/sequence 순서의 개별 체결 N개를 묶고 price×개별수량을 정확히 합산한 기존 결과를 읽기 호환한다. 새 지정봉 UI에는 틱 선택을 노출하지 않는다.
- 분/시는 장 시작 기준 경계다. 수집 시작 이전을 포함하는 봉, 누락 분봉, 미완성봉, 장 종료로 짧아진 잔여 봉은 제외한다. 빈 구간에 가짜 봉을 채우지 않는다.
- 기존 키움 원본 체결 저장소에서 누적량 증가와 개별량이 일치한 수집 구간만 재사용한다. 시작/끝 sequence도 보존한다. 틱 수신 후 원본이 배치 저장된 구간만 사용한다.
- 연결된 키움 국내 계좌의 공식 1분봉은 N분/N시간봉으로 집계한다. 응답에 정확한 체결대금이 없으므로 `(O+H+L+C)/4 × 거래량`을 연구용 근사 거래대금으로 사용하고 결과에 출처와 한계를 표시한다. 틱을 분봉에서 만들거나 다른 주기로 대체하지 않는다.
- 과거 상태/위험/세션 자료는 기존 시점 JSON이 필요하다. 실제 공식 과거 원본 API 연동은 아직 완료되지 않았다.

평균 거래대금·중단기 낙폭·RSI·평균거래량·MA·Pivot·근사 구간 기간은 선택한 **봉 개수**다. 기존 `*Days` 저장 키는 유지한다. 후보 유지/보유/재진입 기간은 명시된 **시장 거래일**이며 분봉 개수로 바꾸지 않는다.

## 계산과 기록

`ViewModel → StrategyBarAggregator → OversoldScreeningEngine → OversoldEntryDetector`로 처리한다. 일봉 백테스트도 동일 EntryDetector와 PositionRules를 사용한다. 스크리닝은 과거부터 후보/반등 저점을 준비하되 가상 체결을 만들지 않는다. 실제 보유·청산·재진입은 백테스트/실행 엔진의 체결 상태가 필요하다.

백테스트 신호와 체결에는 판단 당시 유효 군집 전체와 UsedForEntry, 추가매수 직전 체결/기준/가격·지지 판단, 최초 지지 하단 및 추적 peak/stop을 보존한다. 신호 시각과 실제 모형 체결 시각을 구분한다. 옛 기록의 snapshot이 없으면 재계산하지 않고 없음을 안내한다.

팝업은 같은 `IOversoldBacktestService`를 종목/차트 탭과 공유한다. 일봉 결과는 성과 요약·거래표·▲/▼·Support Zone을 표시하고, 행이나 marker 선택 시 해당 시점으로 이동한다. 이전/다음은 창을 새로 만들지 않고 현재 내용을 교체하며, 빠르게 넘기면 이전 로드를 취소한다. 자세한 내용은 [ScreeningBacktestPopup.md](ScreeningBacktestPopup.md) 참고.

실시간 전략 실행은 선택한 분 또는 시간 기준과 검증된 시장 세션·시점별 상태·위험·준비봉이 모두 있는 경우에만 시작한다. 실시간 모의는 실제 시세를 사용하되 가상 계좌에만 기록하며 증권사 주문 API를 호출하지 않는다. 실계좌 경로는 별도 시작 확인과 주문 직전 중지·계좌 상태 재검증을 거친다.
